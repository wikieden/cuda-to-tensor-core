讲解

第一步：overhead-bound——GPU 在等 CPU（2026-11-14）

第 9 章的第三类"慢"：kernel 本身很短，时间花在启动和间隙上。

数字演示（量级〔旧知〕）：一次 kernel 启动在 CPU 侧要几微秒；LLM decode 一个 token 有几百个 kernel，每个只跑几到几十微秒。假设 300 个 kernel、平均每个 8 微秒、每次启动间隙 4 微秒：

\[\text{总时间} \approx 300 \times (8 + 4) = 3.6 \text{ ms}, \quad \text{其中间隙} = 1.2 \text{ ms（33\%）}\]

在 Nsight Systems 的时间线上（第 9 章），这表现为 GPU 那一行上一段段的空白。本章的三个工具都是为了消灭这些空白。

第二步：stream——一条有序的任务队列（2026-11-14）

PG §2.5.2：stream 是一个按顺序执行的任务队列（kernel、拷贝、event）。同一个 stream 里的任务严格按提交顺序执行；不同 stream 之间的任务可以并发。

cudaStream_t s1, s2;
cudaStreamCreate(&s1); cudaStreamCreate(&s2);

cudaMemcpyAsync(dA, hA, bytes, cudaMemcpyHostToDevice, s1);   // 拷贝走 s1
kernelX<<<g, b, 0, s1>>>(dA);                                 // 第四个参数是 stream
kernelY<<<g, b, 0, s2>>>(dB);                                 // 和 s1 里的东西可以同时跑
cudaStreamSynchronize(s1);

两个经典用法：

  1. 拷贝与计算重叠（Best Practices §10.1.2）：把数据切成几段，第 k 段在算的时候第 k+1 段在拷。要求 host 内存是锁页内存（cudaMallocHost，第 4 章），而且用 cudaMemcpyAsync。GPU 有独立的拷贝引擎，拷贝和 kernel 真能同时进行。
  2. 独立的小 kernel 并发（Best Practices §11.5）：两个都填不满 GPU 的 kernel，放进不同 stream 可以一起跑。

stream 之间要有依赖时，用 event：cudaEventRecord(e, s1); cudaStreamWaitEvent(s2, e);——s2 后面的任务要等 s1 走到 e 这一步。

一个坑（PG §2.5.6）：默认 stream（legacy default stream）会和其他所有 stream 同步，不小心用了它，并发就没了。编译时加 --default-stream per-thread 或者显式创建 stream。

第三步：CUDA Graphs——录一次，重放多次（2026-11-14）

PG §2.5.9.2：很多程序会反复执行同一串操作（比如每生成一个 token 都跑一遍同样的几百个 kernel）。CUDA Graphs 把这串操作做成一张图：

  1. 捕获（capture）：第一次执行时，用 stream capture 把提交到 stream 的操作录下来（也可以用 Graph API 手工搭）；
  2. 实例化（instantiate）：做一次，把运行时需要的结构全部准备好；
  3. 执行（launch）：之后每次只要一次 cudaGraphLaunch，整张图的几百个 kernel 一起提交，CPU 开销几乎为零。
cudaStreamBeginCapture(s, cudaStreamCaptureModeGlobal);
for (int l = 0; l < 32; l++) { attn<<<..., s>>>(...); mlp<<<..., s>>>(...); }
cudaStreamEndCapture(s, &graph);
cudaGraphInstantiate(&exec, graph, 0);
for (int t = 0; t < n_tokens; t++) cudaGraphLaunch(exec, s);   // 每个 token 一次提交

限制：图是"录下来"的，形状、指针在重放时不能随意变（可以用 Graph Update 改参数，PG §4.2.3；变化太多就要多录几张，比如每种 batch 大小一张）。PyTorch 的 torch.cuda.CUDAGraph 和 torch.compile(mode="reduce-overhead") 就是这个；vLLM / SGLang 的 decode 默认用 CUDA Graphs。

第一步例子里那 1.2 ms 的启动间隙，用 Graph 后基本消失。

第四步：PDL——前一个还没完，后一个先热身（2026-11-14）

Graph 去掉了 CPU 侧的启动开销，但 GPU 侧还有一个空隙：前一个 kernel 的最后几个 block 在收尾时，大部分 SM 已经闲了；后一个 kernel 要等前一个全部结束才能开始，开始后还要做一段准备工作（PG §4.5.1 说的 "preamble"：清零 buffer、读常量、算地址、初始化 barrier……）。

Hopper（CC 9.0）的 PDL（PG §4.5）：

  • 前一个 kernel（primary）在不再产生后续需要的数据时调用 cudaTriggerProgrammaticLaunchCompletion()，发信号"后面的可以开始了"；不调的话，等所有 block 退出时隐式触发；
  • 后一个 kernel（secondary）以 PDL 属性启动，可以提前在空出来的 SM 上开始，先做不依赖前者结果的准备工作；
  • 用到前者结果之前，必须调用 cudaGridDependencySynchronize() 等前者的数据就绪——PG 原话：依赖并发执行而不这样同步是不安全的，可能死锁。
__global__ void secondary(...) {
    // 准备工作：不依赖 primary 的结果
    init_shared_memory(); compute_addresses();
    cudaGridDependencySynchronize();       // 等 primary 的结果可见
    // 正式计算
}
// 启动：cudaLaunchKernelEx + cudaLaunchAttributeProgrammaticStreamSerialization

PDL 可以和 CUDA Graphs 一起用（PG §4.5.3：stream capture 或 cudaGraphDependencyTypeProgrammatic 边）。PG 也提醒：重叠是"机会性的"，不保证一定发生——要用 Nsight Systems 实测（04 调研 §1.1）。CUTLASS 的 Hopper / Blackwell kernel 已经内置了 PDL 支持。

第五步：三件工具的分工（2026-11-14）

工具 消掉的是什么 前提 / 代价
streams + 异步拷贝 拷贝和计算之间、独立 kernel 之间的串行等待 锁页内存；任务之间真的独立
CUDA Graphs CPU 侧每次启动的开销 同一串操作重复执行；形状固定或按形状分别录
PDL GPU 侧相邻 kernel 之间的收尾 / 准备空隙 CC ≥ 9.0；后一个 kernel 有可以提前做的准备工作
融合 / megakernel（第 21、23 章） kernel 边界本身 开发成本高

数学原理

  • 启动开销占比：\(n\) 个 kernel、平均运行 \(t_k\)、间隙 \(t_g\)，间隙占比 \(= t_g / (t_k + t_g)\)；\(t_k\) 越小占比越大。
  • 分段重叠：数据切 \(s\) 段、拷贝总时间 \(T_c\)、计算总时间 \(T_k\)，理想流水后 \(\approx \max(T_c, T_k) + \min(T_c, T_k)/s\)（和第 16 章的流水线公式同一结构）。

关键几行：

start = stream_free.get(stream, 0.0)          # 同一 stream：等前一个任务做完
for a, b in sorted(busy.get(engine, [])):     # 同一引擎：找最早放得下的空闲
    if start + dur <= a:
        break
    start = max(start, b)
busy.setdefault(engine, []).append((start, start + dur))

代码里才看得到的 3 件事：

  1. 两个引擎：copy 和 compute：GPU 有独立的拷贝引擎，所以拷贝和 kernel 真能同时进行；模型里同一引擎一次只做一件事，不同引擎互不影响。
  2. launch_timeline 的 PDL 是理想情况：假设后一个 kernel 的准备工作完全藏进前一个的计算；PG 说重叠是"机会性的"，要用 Nsight Systems 实测。
  3. 第三、四步的 µs 数是编的：只为看三种方式谁快，讲义里只有第一步那组数是讲义给的。
