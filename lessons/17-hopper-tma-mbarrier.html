本章缩写：TMA = Tensor Memory Accelerator（张量 / 内存 / 加速器）· mbarrier = memory barrier（PTX 里的共享内存屏障对象，可按字节计数）· CTA = Cooperative Thread Array（协作线程数组，即 block）· DSMEM = Distributed Shared MEMory（分布式共享内存）· GPC = Graphics Processing Cluster（若干 SM 组成的硬件集群）· OOB = Out Of Bounds（越界）

讲解

第一步：TMA——专门的搬运工（2026-11-14）

Ampere 的 cp.async 已经异步了，但还有两个负担：

  1. 每个线程搬自己那 16 字节：128 × 64 的 BF16 tile（16 KB）要 1024 次 16 字节拷贝，每个线程都要算自己的源地址、目标地址、要不要越界保护；
  2. 占着线程的指令发射槽：这些地址运算和拷贝指令都和计算抢同一个 warp 的发射机会。

Hopper（CC 9.0）的 TMA 是 SM 里一个独立的硬件单元。PG §4.12.2：它的主要目标是"为多维数组提供从全局内存到 shared memory 的高效搬运"，把"容易出错且重复的地址计算"卸载给硬件。

类比：以前每个厨师自己去仓库搬菜；现在有了专门的搬运工，厨师只要递一张单子"把第 3 行第 5 列那一箱搬来"，就接着做菜。

第二步：tensor map——事先写好的"仓库地图"（2026-11-14）

TMA 怎么知道一个 tile 在显存里长什么样？靠 tensor map（PTX §5.5）：在 host 端用 cuTensorMapEncodeTiled 生成一个描述符，写明：

  • 全局张量的基地址、维数（最多 5 维）、每维大小和步长（stride）；
  • tile（box）的大小；
  • shared memory 里用哪种 swizzle（32B / 64B / 128B，第 15 章）；
  • 越界时填 0 还是其他。

这个描述符作为 const __grid_constant__ 参数传给 kernel（PG 原文）。kernel 里一条指令：

cp.async.bulk.tensor.2d.shared::cluster.global.mbarrier::complete_tx::bytes
    [smem_dst], [tensor_map, {x, y}], [mbar];

意思是："按这张地图，把坐标 (x, y) 处的那个 tile 搬到 smem_dst，搬完了在 mbar 上记账。"只要一个线程发。

Colfax 的博客强调两个省心的地方：

  • 越界自动处理：tile 有一部分超出矩阵边界时，TMA 自动不读越界部分（填 0），不用自己写 if（第 1 章的越界检查交给硬件）；
  • 一个限制：全局张量除最内层外的每个 stride 必须是 16 字节的倍数。FP32 行优先矩阵就要求列数 n % 4 == 0，不满足要先 padding。

方向也不只是读：TMA 可以 shared → global 写回（TMA store），可以做 store 时顺便归约（cp.reduce.async.bulk.tensor），还可以 multicast——一次从显存读，同时写进 cluster 里多个 block 的 shared memory（第五步）。

第三步：mbarrier——按字节记账的栅栏（2026-11-14）

TMA 是一个线程发起、硬件在后台搬的。其他线程怎么知道数据到了？第 16 章的 wait_group 只管"自己发的"，不够用。

Hopper 的 mbarrier（PTX §9.7.15.16）是放在 shared memory 里的一个 64 位对象，同时记两个数：

  • 还要多少次 arrive（线程报到）；
  • 还要多少字节的交易（transaction）——TMA 每搬完一部分就自动减掉相应字节数。

Colfax 博客里的标准用法（CuTe 封装 → 底层 PTX）：

① 线程 0：mbarrier.init(mbar, 1)                         // 期望 1 次 arrive
② 线程 0：mbarrier.arrive.expect_tx(mbar, 16384)         // 报到，并声明"还要来 16384 字节"
③ 线程 0：cp.async.bulk.tensor ... [mbar]                // 发起 TMA，搬完时自动给 mbar 记 16384 字节
④ 所有线程：mbarrier.try_wait.parity(mbar, phase)        // 等 arrive 和字节都清零

④ 之后，PG / Colfax 保证：TMA 写进 shared 的数据对所有等过这个 mbarrier 的线程可见。

和第 16 章的异步 barrier 一样，mbarrier 也有相位：计数清零后自动翻转相位位（parity）、重置计数，可以下一轮再用。流水线里每个 stage 配一个 mbarrier，用相位位区分"这是第几圈"。

第四步：thread block cluster——几个 block 绑成一组（2026-11-14）

第 2 章的规矩：block 之间不能互相等。Hopper 开了一个口子（PG §1.2.2.1.1）：

  • 可以把相邻的几个 block 组成一个 cluster（一维、二维或三维）；
  • 同一 cluster 的 block 保证同时被调度到同一个 GPC（若干相邻 SM）上运行；
  • 所以它们之间可以同步（cluster.sync()），可以直接读写对方的 shared memory——这叫 分布式 shared memory（DSMEM）（PG §2.3.3.8）。
__global__ void __cluster_dims__(2, 1, 1) k(...) {          // 每 2 个 block 一组
    namespace cg = cooperative_groups;
    cg::cluster_group cluster = cg::this_cluster();
    __shared__ float buf[256];
    float* peer = cluster.map_shared_rank(buf, cluster.block_rank() ^ 1);   // 拿到伙伴 block 的 buf
    cluster.sync();
    float x = peer[threadIdx.x];                            // 直接读伙伴的 shared memory
    cluster.sync();                                         // 伙伴退出前要保证没人还在读它
}

cluster 大小有上限，依硬件而定（PG 原文："hardware dependent"）；Hopper tuning guide 建议用 cudaOccupancyMaxActiveClusters 来算 cluster kernel 的占用。

第五步：cluster 的两个大用处（2026-11-14）

  1. TMA multicast：GEMM 里，C 的同一行 tile 的几个 block 都要读 A 的同一块。以前各读各的，显存（或 L2）被读好几遍；cluster 里用 multicast，一次读、同时写进几个 block 的 shared memory，显存 / L2 流量按 cluster 大小成倍减少。
  2. 跨 block 归约 / 交换：第 11 章的四层归约多了一层——block 的部分和通过 DSMEM 在 cluster 内合并（Quack 博客的做法），减少全局原子操作或第二个 kernel。

Gordić 的数字（第 63–66 行）：H100 每个 GPC 18 个 SM（满血芯片），但产品里有的 SM 被屏蔽，实际可用的 SM 数不一定是 cluster 大小的整数倍——选 cluster 大小时要考虑这一点。

第六步：Hopper 一个 GEMM 内循环的样子（2026-11-14）

把第 15–17 章拼起来，Hopper GEMM 的一个 stage：

生产者（一个线程）：等"这个 stage 的 buffer 空了" → arrive.expect_tx → TMA 搬 A tile、B tile（可 multicast）
消费者（计算 warp）：等 mbarrier（数据到了）→ wgmma 用 shared 里的 A、B 算 → 通知"buffer 空了"

"谁搬、谁算、怎么通知"——这正是下一章 warp specialization 的主题。

怎么看：

  1. 左边是显存里的矩阵（按 tile 分格），右边是 block 的 shared memory 和一个 mbarrier 计数器；
  2. 线程 0 发出一条 TMA 指令后就去做别的（灰色），TMA 单元把 tile 一块块搬过去，mbarrier 的"剩余字节"往下减；
  3. 字节数归零、相位位翻转，所有线程同时被唤醒；
  4. 切到 cluster = 2：一次读取同时落到两个 block 的 shared memory，显存读取量减半。

口诀

TMA 是专职搬运工：一张仓库地图（tensor map），一个线程一条指令搬整块，越界自动补零；
mbarrier 按人头也按字节记账：expect_tx 先报数，搬完自动扣，清零翻相位；
cluster 把相邻 block 绑一组：同时上岗、能互相等、能翻对方的台面（DSMEM）；
multicast 一次读、几家同时收。

数学原理

  • multicast 的流量节省：cluster 大小 \(c\)，\(c\) 个 block 共享同一块 A tile 时，A 的读取量变为 \(1/c\)；GEMM 的二维 cluster（\(c_m \times c_n\)）可同时让 A 降为 \(1/c_n\)、B 降为 \(1/c_m\)。
  • tile 字节数：\(B_M \times B_K \times\) 每元素字节；expect_tx 填的就是本 stage 所有 TMA 搬运的字节总和。

关键几行：

def arrive_expect_tx(self, nbytes):   # 报到一次，声明"还要来 nbytes 字节"
    self.pending_tx += nbytes
    self.pending_arrive -= 1
    self._maybe_flip()

def complete_tx(self, nbytes):        # TMA 搬完一部分时硬件自动调用
    self.pending_tx -= nbytes
    self._maybe_flip()                # 人头和字节都清零 → 相位翻转、重置

代码里才看得到的 3 件事：

  1. tensor map 的坐标是"第几块"：load_tile(1, 1) 取的是第 1 块行、第 1 块列，即原矩阵第 4–7 行、第 4–7 列；真实 TMA 的坐标是元素坐标，CuTe 会替你换算。
  2. 越界补 0 靠 NumPy 切片自动截断：tensor[4:8, 4:8] 在 5 × 6 的矩阵上只返回 1 × 2，剩下的位置保持 0——TMA 在硬件里做同样的事，kernel 不用写 if。
  3. mbarrier 要人头和字节都清零才翻相位：只报到不等字节、或者字节到了没人报到，都过不去。
