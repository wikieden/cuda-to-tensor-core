本章缩写：CuTe = CUDA Templates（CUTLASS 3 起的核心布局库，读作 "cute"）· CUTLASS = CUDA Templates for Linear Algebra Subroutines（线性代数子程序的 CUDA 模板库）· TV layout = Thread-Value layout（线程–值布局：哪个线程拿哪些值）· DSL = Domain-Specific Language（领域专用语言）

讲解

第一步：所有下标公式都是"坐标点乘步长"（2026-11-14）

回顾一下前面手写过的下标：

章 公式
1 i = blockIdx.x * blockDim.x + threadIdx.x
6 行优先 A[r * N + c]
7 padding tile[r * 33 + c]
13 x = blockIdx.x * 32 + threadIdx.x / 32; y = ... + threadIdx.x % 32

它们都是同一个形状：把一个多维坐标，和一组步长逐项相乘再相加，得到一维的位置。CuTe 把这件事抽象成 Layout（01_layout.md）：

A Layout is a tuple of (Shape, Stride)……it implements a mapping from any coordinate within the Shape to an index via the Stride.

写法是 Shape : Stride，例如 (4, 2) : (1, 4)。坐标 \((i, j)\) 映射到

\[\text{index} = i \cdot 1 + j \cdot 4\]

数字演示：

Layout 含义 (0,0) (1,0) (0,1) (3,1)
(4,2):(1,4) 4 × 2 列优先：一列内相邻元素相差 1 0 1 4 7
(4,2):(2,1) 4 × 2 行优先：一行内相邻元素相差 1 0 2 1 7
(4,2):(1,5) 列优先，每列多 1 个 padding 0 1 5 8

同一个"4 × 2 的矩阵"，换个 Stride 就换了存储方式，用它的代码一个字都不用改——这正是文档开头说的："a row-major MxN layout and a column-major MxN layout can be treated identically in software."

不写 Stride 时默认 LayoutLeft：步长是 Shape 从左往右的累乘（第 159 行），即"广义列优先"。注意这和 C 数组的行优先习惯相反。

第二步：层次化 Shape——一个维度还能再拆（2026-11-14）

CuTe 的 Shape 和 Stride 可以嵌套（IntTuple 的递归定义）：(4, (2, 2)) : (2, (1, 8))。第二维看起来是"4 个"，其实内部又分成 2 × 2，各有自己的步长。

这能表达普通二维下标写不出来的布局，比如"每 2 列交错存放"、Tensor Core fragment 里线程和元素的复杂对应（第 15 章的 Figure 82 就是这样一个 layout）。

一维坐标怎么对应多维坐标？ CuTe 用 colexicographical 顺序（01_layout.md 第 381 行：从右往左读、最左边的维变化最快）：对 Shape (4, 2)，一维坐标 0, 1, 2, 3, 4… 对应 (0,0), (1,0), (2,0), (3,0), (0,1)…。于是每个 Layout 都可以当作"一维下标 → 位置"的函数来用。

第三步：layout 代数——分块就是除法（2026-11-14）

把 layout 看成函数，就可以对它做运算（02_layout_algebra.md）：

运算 意思 用在哪
composition A ∘ B 先用 B 把坐标变一次，再交给 A：函数复合 重排、reshape、swizzle
logical_divide A / tile 把 A 按 tile 切块：结果第一维是"块内"，第二维是"第几块" 第 13 章的 block tile、第 14 章的 thread tile
logical_product A × B 把 A 复制 B 次排成更大的布局 一个 MMA 原子重复铺满整个 warp tile
complement A 没覆盖到的那部分 divide 的内部实现

例子：一个 8 × 8 的矩阵按 4 × 4 分块，zipped_divide(layout, Shape<_4,_4>{}) 得到形如 ((4,4), (2,2)) 的 layout——第一维是块内坐标，第二维是块号。block (bx, by) 只要取第二维固定为 (bx, by) 的那一片，就拿到了自己的 tile，再也不用手写 blockIdx.x * BM + ...。

第四步：Tensor 与按线程切分（2026-11-14）

Tensor = 指针 + Layout（03_tensor.md）。有了 Tensor，GEMM 的一层层分块写成（0x_gemm_tutorial.md 的 sgemm_1.cu）：

Tensor mA = make_tensor(make_gmem_ptr(A), make_shape(M, K), dA);          // 整个 A
Tensor gA = local_tile(mA, cta_tiler, cta_coord, Step<_1, X, _1>{});     // 本 block 的 tile（沿 K 还有多块）
Tensor sA = make_tensor(make_smem_ptr(smemA), sA_layout);                 // shared 里的 tile
Tensor tAgA = local_partition(gA, tA, threadIdx.x);                       // 本线程负责搬的那部分
Tensor tAsA = local_partition(sA, tA, threadIdx.x);
copy(tAgA(_,_,k), tAsA);                                                  // 搬

tA 是一个线程布局（比如 32 × 8 个线程怎么排），local_partition 用它把 tile 切给每个线程——第 6 章"让 threadIdx.x 对应最快变化的那一维"变成了"选一个合适的线程 layout"。

再往上一层，CuTe 把硬件指令包装成 Atom（0t_mma_atom.md）：MMA_Atom 描述一条 mma.sync / wgmma / tcgen05.mma 需要的 TV layout（哪个线程拿哪些值），Copy_Atom 描述一条 cp.async / ldmatrix / TMA。再用 TiledMMA、TiledCopy 把原子铺满整个 tile。换架构时主要是换 Atom，算法结构不用变——这就是 sgemm_1 → sgemm_2 → sgemm_sm80 → hopper/wgmma_tma_sm90 那条教程线的意义（study-plan M6）。

第五步：swizzle 也是一个 layout（2026-11-14）

第 7、15 章的 swizzle（地址异或重排防 bank conflict）在 CuTe 里是 Swizzle<B, M, S> 函数，和普通 layout 复合：composition(Swizzle<3,3,3>{}, smem_layout)。TMA 的 tensor map 里选的 128B swizzle 模式、wgmma 要求的 shared memory 布局（Colfax WGMMA 博客 "SMEM layout constraints"），在 CuTe 里就是几个预定义的 layout atom。

第六步：为什么值得学，以及 CuTe DSL（2026-11-14）

  • CUTLASS 3/4 全部建立在 CuTe 上；FlashAttention-3 用 CuTe C++，FlashAttention-4、Quack 用 CuTe DSL（Python 写，编译快 20–30 倍，02 生态 自测题 3）。读这些代码，绕不开 layout 记号。
  • Rust 没有对应物（03 Rust vs C++ §3），这是 C++ / Python 路线目前的独有优势。
  • 学习曲线陡：先把 (Shape):(Stride) 和 divide 弄熟，再看 TiledMMA。GPU MODE L57 是一个很好的入门讲座。

口诀

下标都是坐标点乘步长：Layout = Shape : Stride；
不写步长默认左边快（列优先），和 C 数组反着来；

分块是除法，铺满是乘法，重排是复合，swizzle 也是一个 layout；

数学原理

  • Layout 是函数：\(L: \mathbb{Z}^{\text{shape}} \to \mathbb{Z}\)，\(L(c) = \sum_i c_i s_i\)（对嵌套 shape 递归展开）。
  • colexicographical 一维化：Shape \((n_0, n_1, \dots)\) 下，一维坐标 \(x\) 对应 \(c_0 = x \bmod n_0\)，\(c_1 = \lfloor x / n_0 \rfloor \bmod n_1\)，……
  • composition：\((A \circ B)(c) = A(B(c))\)；divide 用 composition 加 complement 定义（02_layout_algebra.md 第 381–414 行）。
  • cosize：\(L(\text{size}-1) + 1\)，layout 实际用到的内存跨度（padding 时大于 size）。

关键几行：

class Layout:
    def __init__(self, shape, stride=None):
        self.stride = stride or left_strides(shape)   # 默认：Shape 从左往右累乘
    def __call__(self, coord):
        if isinstance(coord, int):                     # 一维坐标 → 多维（colex）
            coord = idx2crd(coord, self.shape)
        return sum(c * d for c, d in zip(flatten(coord), flatten(self.stride)))

代码里才看得到的 3 件事：

  1. NumPy 默认是行优先，CuTe 默认是列优先：验证分块时要写 np.arange(64).reshape(8, 8, order="F")（F = Fortran 顺序，即列优先），不然对不上。
  2. 嵌套坐标先摊平再点乘：(1, (1, 1)) 摊平成 1、1、1，和摊平的步长 2、1、8 点乘——这就是"层次化 Shape"在计算上的全部意思。
  3. zipped_divide_2d 只是 2D 的特例：CuTe 的 logical_divide 对任意嵌套 layout 都成立，靠的是 complement 和 composition；这里只演示结果长什么样。
