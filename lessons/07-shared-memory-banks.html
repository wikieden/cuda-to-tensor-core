本章缩写：SMEM = Shared MEMory（共享内存）· bank（存储体，shared memory 的一个独立通道）

讲解

第一步：shared memory——block 内的公共台面（2026-11-14）

PG §2.3.3.2：shared memory 是一个 block 内所有线程都能访问的片上内存，和 L1 是同一块物理存储；生命周期和 block 一样长。它像一块"程序员自己管的草稿纸"。

两种声明方式：

__shared__ float tile[32][32];            // 静态：大小编译时定

extern __shared__ float buf[];            // 动态：大小启动时定
kernel<<<grid, block, 4096>>>(...);       // 第三个参数 = 动态 shared 的字节数

典型用法是第 5 章说的"读一次、用多次"和第 6 章说的"转置中转"。

第二步：__syncthreads()——等所有人放好再拿（2026-11-14）

shared memory 是公用的，就会有谁先谁后的问题。

__shared__ float s[256];
s[threadIdx.x] = g[i];                 // ① 每个线程放一个数
__syncthreads();                       // ② 等 block 里所有线程都放完
float y = s[255 - threadIdx.x];        // ③ 读别人放的数

没有 ②，线程 0 去读 s[255] 时，线程 255 可能还没写——读到垃圾值。这叫数据竞争（data race）。__syncthreads() 是一道栅栏（barrier）：PG §2.3.2.1，block 里所有线程都到达这里之后，谁都才能继续，并且之前的 shared / global 写对 block 内其他线程可见。

两条铁律：

  1. "写完再读"之间要一道栅栏；"读完再覆盖"之间也要一道（循环里反复用同一块 shared memory 时，下一轮写之前要确保这一轮所有人都读完了）。
  2. __syncthreads() 必须被 block 里所有线程走到。 写在 if 里、只有部分线程能到达，就是未定义行为，常见结果是死锁（本仓库 cubecl-lab M1 的注释里专门提醒过这个坑）。

第三步：32 个 bank——shared memory 也有车道（2026-11-14）

PG §2.3.4.2 原文：

shared memory 有 32 个 bank，连续的 32 位字（4 字节）依次映射到连续的 bank；每个 bank 每个周期能给出 32 位。

也就是：地址（以 4 字节为单位）为 w 的字，在第 w % 32 号 bank 上。

类比：32 个窗口的食堂。 第 0 个字在 0 号窗口，第 1 个字在 1 号窗口……第 32 个字又回到 0 号窗口。一个 warp 的 32 个人同时来打饭：

  • 32 个人去了 32 个不同窗口 → 一个周期全部打完；
  • 有几个人去了同一个窗口、要不同的菜 → 只能排队，一个一个打。这就是 bank conflict（存储体冲突）；同一窗口最多排了几个人，就叫几路冲突（n-way），耗时变成 n 倍；
  • 几个人去同一窗口、要同一份菜（同一个地址）→ 不冲突，广播（broadcast）给所有人（PG 原文的例外情况）。

第四步：算冲突——跨步访问（2026-11-14）

warp 里线程 t 读 s[t * stride]（float）：

stride 线程 t 的 bank 几路冲突
1 t % 32 无冲突
2 2t % 32：只用到偶数号 16 个 bank 2 路
3 3t % 32：3 和 32 互质，32 个 bank 各一次 无冲突
4 只用到 8 个 bank 4 路
32 全部是 0 号 bank 32 路（最坏）

规律：几路冲突 = \(\gcd(\text{stride}, 32)\)（最大公约数）。奇数跨步永远不冲突。

最经典的场景：二维 shared 数组按列读（PG §2.3.4.2.2）。

__shared__ float tile[32][32];
float x = tile[threadIdx.x][c];   // warp 里 32 个线程读同一列

tile[r][c] 的字地址是 r * 32 + c，bank = (r * 32 + c) % 32 = c——一整列全在同一个 bank 上，32 路冲突。按行读 tile[c][threadIdx.x] 则 bank = threadIdx.x，没有冲突。

第五步：padding——每行多放一个（2026-11-14）

__shared__ float tile[32][33];    // 每行 33 个，多出来的 1 个不用

现在 tile[r][c] 的字地址是 r * 33 + c，bank = (r * 33 + c) % 32 = (r + c) % 32。同一列 c 固定、r 从 0 到 31，bank 正好是 32 个不同的值——冲突消失。代价只是多用 32 个 float（3%）的 shared memory。

这一招让矩阵转置变得完整：按行读显存（合并）→ 写进 tile → 同步 → 按列读 tile（padding 后不冲突）→ 按行写显存（合并）。

Hopper 以后更常用的是 swizzle（异或重排地址）：不浪费空间，用 col ^ row 之类的变换把同一列打散到不同 bank。TMA 和 CuTe 都内置了几种 swizzle 模式（第 17、19 章）。

口诀

shared 是 block 的公共台面，写完要等、读完再覆盖也要等；
__syncthreads() 要全员到场，别写在 if 里；
32 个窗口轮着排，字地址模 32 就是窗口号；
同窗不同菜要排队，同窗同菜一起打；冲突路数 = gcd(跨步, 32)，奇数跨步不冲突；
按列读二维数组冲突 32 路，每行多放一个就散开。

本章复习卡片

  • C15（__syncthreads() 的两条铁律：写后读、读后覆盖都要栅栏；必须全员到达）
  • C16（bank：32 个、4 字节一个、bank = 字地址 % 32；n 路冲突 = 同 bank 不同地址的最大数；广播例外）
  • C17（二维 [32][32] 按列读 32 路冲突；[32][33] padding 后 bank = (r + c) % 32，无冲突）

数学原理

  • bank 映射：字地址 \(w\)（字节地址 ÷ 4）在 bank \(w \bmod 32\)。
  • 跨步冲突：线程 \(t\) 访问 \(w_t = s \cdot t + b\)，bank 为 \((st + b) \bmod 32\)，用到的 bank 数 \(= 32/\gcd(s, 32)\)，冲突路数 \(= \gcd(s, 32)\)。
  • padding：行宽 \(32 + 1\) 时，\((r(32+1) + c) \bmod 32 = (r + c) \bmod 32\)，对固定 \(c\)、\(r = 0..31\) 两两不同。

关键几行：

def bank(word_addr):                       # 第 w 个 4 字节字在 w % 32 号 bank
    return word_addr % 32

def conflict_ways(word_addrs):             # 同一 bank 上不同地址最多几个
    distinct = np.unique(word_addrs)       # 同一地址只算一次（广播）
    return np.bincount(bank(distinct), minlength=32).max()

tile_addr(r, c, 33)                        # tile[32][33]：r * 33 + c

代码里才看得到的 2 件事：

  1. 先 np.unique 再数：同一个地址被几个线程同时读是广播，不算冲突；不去重的话"32 个线程都读 s[0]"会被错算成 32 路。
  2. race_demo(False) 是"最坏的交错"之一：真实 GPU 上没有栅栏时读到什么取决于调度，可能碰巧全对，也可能全错——"碰巧全对"正是数据竞争难查的原因。
