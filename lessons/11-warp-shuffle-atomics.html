讲解

第一步：shuffle——同一个 warp 里直接递纸条（2026-11-14）

第 10 章的树形归约每一轮都要：写 shared memory → __syncthreads() → 读 shared memory。如果参与的线程都在同一个 warp 里，可以更快：warp shuffle 让一个线程直接读另一个 lane 寄存器里的值，不经过 shared memory，也不需要 block 级同步（PG §5.4.6.5："exchange a value……without the use of shared memory"）。

类比：同一排的同学直接递纸条，不用先放到讲台（shared memory）上再去拿。

四种（Oxford lec4 第 2 页）：

函数 从哪个 lane 拿 用途
__shfl_sync(mask, v, src) 指定的 lane src 广播：大家都拿 lane 0 的值
__shfl_up_sync(mask, v, d) lane − d（比自己小 d） 前缀和（下一章）
__shfl_down_sync(mask, v, d) lane + d（比自己大 d） 归约
__shfl_xor_sync(mask, v, m) lane XOR m 蝴蝶归约，结果所有 lane 都有

参数 mask 说明哪些 lane 参与，一般填 0xffffffff（32 个 1，全员）。名字里的 _sync 就是第 3 章说的：Volta 以后要显式说明谁和谁同步。Oxford 第 5 页的警告：只能读正在参与这次 shuffle 的 lane，目标 lane 不活跃时拿到的值是未定义的——写在 if 里时要特别小心。

第二步：5 步加完 32 个数（2026-11-14）

float v = ...;                                    // 每个 lane 一个数
for (int d = 16; d > 0; d /= 2)
    v += __shfl_down_sync(0xffffffff, v, d);      // 加上 lane + d 的值
// 现在 lane 0 的 v 是 32 个数的和

数字演示（缩成 8 个 lane，d 从 4 开始；值 [3, 1, 4, 1, 5, 9, 2, 6]）：

步 d lane 0–3 各加上谁 lane 0–3 的值
1 4 lane t + lane t+4 8, 10, 6, 7
2 2 lane t + lane t+2 14, 17, —
3 1 lane 0 + lane 1 31

和第 10 章的"前一半加后一半"一模一样，只是数据在寄存器之间直接走。32 个 lane 要 \(\log_2 32 = 5\) 步。（后面几步里 lane 4 以上也在算，只是算出来的值没人用，这不要紧——它们反正和 lane 0 在同一个 warp 里，在同一条指令里一起执行。）

用 __shfl_xor_sync 的版本（Oxford 第 6 页方法 1）：for (i = 1; i < 32; i *= 2) v += __shfl_xor_sync(-1, v, i);——每一步 lane 和"编号差一个二进制位"的伙伴互换相加，5 步后每个 lane 都拿到总和，省掉一次广播。

CC 8.0 起还有现成的整数版：__reduce_add_sync(mask, v)（PG §5.4.6.4）；CCCL 里有 cub::WarpReduce。

第三步：归约分层（2026-11-14）

把第 10 章和本章合起来，一个高效的 block 归约是这样分层的（Oxford 第 16 页的提示，也是 Quack 博客的模板）：

  1. 线程内：grid-stride 循环，在寄存器里顺序加很多个数（第 10 章）；
  2. warp 内：5 次 shuffle，每个 warp 的 lane 0 拿到 warp 的和；
  3. block 内：每个 warp 的 lane 0 写一个数到 __shared__ float ws[32]（最多 32 个 warp），__syncthreads()，再让第 0 个 warp 读这 32 个数、再做一次 5 步 shuffle；
  4. 全局：block 的 0 号线程 atomicAdd 到总和（或写部分和，再起一个 kernel）。

和纯 shared memory 的树形归约比，8 轮里有 5 轮不碰 shared memory、不做 block 同步。Quack 博客还多一层：Hopper 的 thread block cluster 可以在几个 block 之间用分布式 shared memory 再归约一层（第 17 章）。

第四步：原子操作——"读-改-写"一次做完（2026-11-14）

多个线程同时做 total += x，普通写会出问题：两个线程都读到旧值 10，各加自己的数，各写回去——其中一个的加法丢了。PG §3.2.2.1 的 Note 也说过，同一 warp 多个线程普通写同一地址，留下谁的值是未定义的。

原子操作把"读、改、写"做成不可打断的一步，硬件保证不丢（PG §2.3.5）：

atomicAdd(&total, x);       // 还有 atomicMax / atomicMin / atomicExch / atomicCAS / atomicAnd ...

数字演示：1000 个线程各 atomicAdd(&total, 1)，结果一定是 1000；改成 total += 1，结果是 1 到 1000 之间不确定的某个数。

代价：同一个地址上的原子操作必须排队一个一个做。所以：

  • ✅ 每个 block 一次原子加：几百上千次，很快；
  • ❌ 每个线程一次原子加到同一个地址：1 亿次排队，很慢——这正是第三步要先在 warp、block 内归约的原因；
  • 地址分散的原子操作（比如直方图，第 12 章前后会碰到）冲突少，通常还行。

更通用的原子：CAS。atomicCAS(addr, expected, desired)：如果 *addr == expected 就改成 desired，返回旧值。用它可以拼出任何原子运算，甚至一把锁（Oxford lec4 第 19 页：do {} while (atomicCAS(&lock, 0, 1));）。但 GPU 上用锁要非常小心——同一 warp 里一个线程拿着锁、另一个在等，老架构上会死锁（第 3 章的独立线程调度就是为了缓解这类问题）。

口诀

同一个 warp 直接递纸条，不过讲台、不用全班等；
down 往大号拿，up 往小号拿，xor 找二进制伙伴，sync 指名道姓；
32 个数 5 步加完：16、8、4、2、1；
归约四层：线程里多加，warp 里 shuffle，block 里 shared，全局原子加；
原子不丢账但要排队：一个 block 一次可以，一个线程一次太慢。

数学原理

  • shuffle 归约步数：\(\log_2 32 = 5\)；down 版本第 \(k\) 步（\(d = 16/2^{k-1}\)）后 lane \(t < d\) 的值 = 原来 lane \(t, t+d, t+2d, \dots\) 中 \(32/d\) 个数之和。
  • xor 蝴蝶：第 \(k\) 步 lane \(t\) 与 \(t \oplus 2^{k-1}\) 交换相加；归纳可证 \(k\) 步后每个 lane 持有"与自己只在低 \(k\) 位不同的 \(2^k\) 个 lane"的和，5 步后为全体之和。
  • 原子操作的串行化：同一地址 \(m\) 次原子更新，最少耗时 ∝ \(m\)；先在 block 内归约把 \(m\) 从"线程数"降到"block 数"。

关键几行：

def shfl_down(v, d):                    # NumPy 数组 = 一个 warp 每个 lane 的寄存器
    src = np.arange(len(v)) + d
    src[src >= len(v)] = np.arange(len(v))[src >= len(v)]   # 超出 warp 的拿回自己的值
    return v[src]

while d > 0:
    v = v + shfl_down(v, d)             # v += __shfl_down_sync(0xffffffff, v, d)
    d //= 2

代码里才看得到的 3 件事：

  1. 所有 lane 都在算：warp_sum_down 每一步对整个数组做加法，lane 4 以上也算出了值（打印出来不是讲义表里的"—"），只是没人用——和讲义说的"它们在同一条指令里一起执行"一致。
  2. 超出范围的 lane 拿回自己的值：这是 CUDA 对 __shfl_down_sync 的规定；所以最后几个 lane 的"和"是错的，只有 lane 0 是对的。
  3. counter(atomic=False) 的交错是随机打乱的：模拟里每个线程的"读"和"写"之间可以插进任意多别人的操作，所以丢得特别多；真实 GPU 上丢多少取决于调度，结果每次都可能不同。
