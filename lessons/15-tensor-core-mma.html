本章缩写：MMA = Matrix Multiply-Accumulate（矩阵 / 乘 / 累加，D = A × B + C）· WMMA = Warp Matrix Multiply-Accumulate（warp 级矩阵乘累加，C++ API）· TF32 = TensorFloat-32（19 位有效精度的 Tensor Core 浮点格式）· BF16 = Brain Float 16（Google Brain 提出的 16 位浮点：8 位指数、7 位尾数）· FP16 = 16 位浮点（5 位指数、10 位尾数）· HMMA = Half-precision MMA（SASS 里的 Tensor Core 指令名）· m16n8k16 = M=16、N=8、K=16 的矩阵乘形状

讲解

第一步：Tensor Core——专门做小矩阵乘的车间（2026-11-14）

到第 14 章为止，乘加都在 CUDA core（普通的标量 FMA 单元）上做：一条指令一个线程算 1 次乘加。

Volta（CC 7.0）起，每个 SM 里多了 Tensor Core：一条指令让一个 warp 合作算一个小矩阵乘，比如 \(16 \times 8 \times 16\)——一次 2048 次乘加。Gordić（第 69 行）："Large matrix multiplications are decomposed into many such tile operations."

算力差多少？ H100 SXM 规格（〔旧知〕）：FP32 CUDA core 约 67 TFLOP/s；BF16 Tensor Core 稠密约 989 TFLOP/s——约 15 倍。Boehm 的 A6000 上 TF32 / BF16 Tensor Core 比 FP32 快 2.5–3.5 倍（blog-boehm… 第 21 行）。训练和推理里的大矩阵乘几乎全跑在 Tensor Core 上；第 14 章那套 FP32 优化是为了学原理。

代价是精度和格式受限：输入是 FP16 / BF16 / TF32 / FP8 / INT8 等低精度，累加器一般是 FP32（PG §5.4.11.6 的类型表）。

第二步：WMMA——C++ 的"黑盒"接口（2026-11-14）

PG §5.4.11：nvcuda::wmma 命名空间，最直观的一套 API：

#include <mma.h>
using namespace nvcuda;

wmma::fragment<wmma::matrix_a, 16, 16, 16, half, wmma::row_major> a;
wmma::fragment<wmma::matrix_b, 16, 16, 16, half, wmma::col_major> b;
wmma::fragment<wmma::accumulator, 16, 16, 16, float> c;

wmma::fill_fragment(c, 0.0f);
for (int k = 0; k < K; k += 16) {
    wmma::load_matrix_sync(a, A + row * K + k, K);     // warp 32 个线程合作读一个 16×16 小块
    wmma::load_matrix_sync(b, B + k * N + col, N);
    wmma::mma_sync(c, a, b, c);                        // c = a × b + c，一条"指令"
}
wmma::store_matrix_sync(C + row * N + col, c, N, wmma::mem_row_major);

关键概念 fragment（片段）：PG 原话 "a section of a matrix distributed across all threads in the warp"——一个 16 × 16 的小矩阵分散存在 warp 32 个线程的寄存器里，每个线程拿 256 / 32 = 8 个数。WMMA 故意不告诉你哪个数在哪个线程（"unspecified and subject to change"），所以你只能整体 load / mma / store，不能单独改某个元素。

PG 还有一条硬性要求：这些函数必须整个 warp 一起调用，写在 if 里时条件必须对整个 warp 一致，否则"likely to hang"（第 3 章的分岔问题在这里是致命的）。

第三步：mma.sync——PTX 层面，布局公开（2026-11-14）

WMMA 底下是 PTX 指令 mma.sync.aligned.m16n8k16...（Ampere 起的主力，PTX §9.7.16.5）。和 WMMA 的区别是：每个线程手里拿哪几个元素，PTX 文档写得清清楚楚（§9.7.16.5.8 的 Figure 82 起）。

以 BF16 输入、FP32 累加的 m16n8k16 为例（\(D_{16\times8} = A_{16\times16} B_{16\times8} + C_{16\times8}\)）：

矩阵 元素数 每线程拿 寄存器
A（16 × 16） 256 8 个 BF16 4 个 32 位寄存器（每个装 2 个 BF16，.f16x2）
B（16 × 8） 128 4 个 BF16 2 个 32 位寄存器
C / D（16 × 8） 128 4 个 FP32 4 个 32 位寄存器

知道布局就能做 WMMA 做不了的事：在累加器上直接做 epilogue（加 bias、激活、量化，不用先写回 shared 再读）、自己安排数据怎么从 shared 进寄存器。FlashAttention-2、LeetCUDA 的 HGEMM 都是直接写 mma.sync 的 PTX。

第四步：ldmatrix——一条指令把小矩阵按 fragment 布局搬进寄存器（2026-11-14）

问题来了：A 的 16 × 16 小块在 shared memory 里是按行存的，但 mma.sync 要求每个线程手里拿特定的 8 个元素（分散在不同行）。让每个线程自己去 shared 里一个个挑，指令多、还容易 bank conflict。

PTX §9.7.16.5.15 的 ldmatrix："Collectively load one or more matrices from shared memory for mma instruction"——warp 合作从 shared memory 读 1 / 2 / 4 个 8 × 8 小矩阵，直接按 mma 需要的布局分到各线程寄存器：

ldmatrix.sync.aligned.m8n8.x4.shared.b16  {r0, r1, r2, r3}, [addr];
// 32 个线程各提供一个行地址（4 个 8×8 矩阵 × 8 行 = 32 行），硬件把数据重排到位

.trans 后缀还能顺便转置（B 矩阵常用）。Ampere 以后高性能 GEMM 的标准内循环是：

cp.async 显存 → shared（下一章）  →  ldmatrix shared → 寄存器  →  mma.sync  →  累加器留在寄存器

第五步：shared memory 的 swizzle（2026-11-14）

ldmatrix 的 32 个线程读 32 个行地址。如果 tile 每行正好 64 字节或 128 字节宽，不同行的同一列落在同一个 bank 上——第 7 章的按列冲突又来了。

padding（每行多放一点）可以解决，但会破坏对齐和 TMA 的要求。Tensor Core 时代的标准做法是 swizzle：写入 shared 时把列号和行号做异或（如 col ^ (row % 8)，以 16 字节为单位），让同一"列"在不同行里落到不同 bank；读的时候用同样的公式找回来。CuTe 和 TMA 都内置了 32B / 64B / 128B 三种 swizzle 模式（第 17、19 章）。Gordić 第 746 行："They're swizzled, and ready for tensor core consumption."

第六步：一代比一代大（2026-11-14）

代 指令 谁合作 典型形状 操作数在哪 同步方式
Volta / Turing（CC 7.x） wmma / mma.sync 1 个 warp m16n16k16（WMMA） 寄存器 同步
Ampere（CC 8.x） mma.sync + ldmatrix 1 个 warp m16n8k16 寄存器 同步
Hopper（CC 9.0） wgmma.mma_async 4 个 warp（warpgroup，128 线程） m64nNk16，N 最大 256 A 寄存器或 shared，B 在 shared，累加器在寄存器 异步
Blackwell（CC 10.0） tcgen05.mma 1 个线程发起 最大 m128 / 2-CTA m256 A、B 在 shared，累加器在 Tensor Memory 异步

（Gordić 第 747–760 行列了前三种；Blackwell 见第 20 章。）趋势很清楚：每条指令越来越大、越来越异步、越来越不占寄存器——为了让 Tensor Core 不停地算，数据搬运和指令发射都要从计算里拆出去。第 16–20 章就是沿着这条线讲。

口诀

Tensor Core 一条指令做一个小矩阵乘，一个 warp 一起干；
低精度进、FP32 累加，比 CUDA core 快一个数量级；
fragment 把小矩阵拆进 32 个线程的寄存器：WMMA 不告诉你谁拿哪个，mma.sync 写在 PTX 里；
ldmatrix 一条指令按布局搬进寄存器，swizzle 让它不撞 bank；
一代比一代大：warp → warpgroup → 单线程发起，同步 → 异步。

数学原理

  • MMA 的计算量：形状 \(m \times n \times k\) 的一次 MMA 做 \(mnk\) 次乘加 = \(2mnk\) FLOP。m16n8k16：2048 次乘加、4096 FLOP。
  • 片段大小：A 有 \(mk\) 个元素分给 32 个线程，每线程 \(mk/32\) 个；B 每线程 \(kn/32\)；D 每线程 \(mn/32\)。
  • 大矩阵分解：\(C_{M \times N} = \sum_{k} A_{:, k\text{-tile}} B_{k\text{-tile}, :}\)，每个 \(16 \times 8\) 的 C 块沿 K 方向累加 \(K/16\) 次 MMA。

关键几行：

def frag_a(lane):                       # PTX §9.7.16.5.8：lane 拿 A 的哪 8 个
    g, t = lane >> 2, lane % 4         # groupID 和 threadID_in_group
    return [(g, 2*t), (g, 2*t+1), (g+8, 2*t), (g+8, 2*t+1),
            (g, 2*t+8), (g, 2*t+9), (g+8, 2*t+8), (g+8, 2*t+9)]

regs = scatter(A, frag_a)              # 形状 (32, 8)：32 个 lane 各 8 个寄存器值
D = gather(d_regs, frag_cd, (16, 8))   # 从 32 个 lane 拼回小矩阵

代码里才看得到的 3 件事：

  1. lane >> 2 和 lane % 4：PTX 文档把 32 个 lane 分成 8 组、每组 4 个，groupID 决定行、组内编号决定列；WMMA 不公开这张表，mma.sync 公开。
  2. 寄存器是 32 位的，一个装两个 BF16：表里 A 的 8 个元素放在 4 个寄存器里，代码只模拟"谁拿哪些元素"，不模拟打包。
  3. 用小整数做测试：A、B、C 取 −3 到 3 的整数，乘加结果是精确的，所以能用 np.array_equal 而不是容差。
