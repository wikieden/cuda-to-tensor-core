本章缩写：CUDA = Compute Unified Device Architecture（计算 / 统一 / 设备 / 架构）· GPU = Graphics Processing Unit（图形 / 处理 / 单元）· CPU = Central Processing Unit（中央 / 处理 / 单元）· SM = Streaming Multiprocessor（流式 / 多处理器）· SIMT = Single Instruction, Multiple Threads（单条指令、多个线程）· PG = Programming Guide（编程指南）· NumPy = Numerical Python（数值 / Python：数组计算库，附录"代码对照"用它在 CPU 上模拟）

讲解

第一步：从"一个人跑循环"到"一人一个数"（2026-11-10）

先看 CPU 怎么做向量加法：

for (int i = 0; i < n; i++)
    c[i] = a[i] + b[i];

一个 CPU 核心从 i = 0 跑到 i = n-1，一次算一个。n = 100 万就要跑 100 万轮。

GPU 的思路反过来：不写循环，只写循环体——"处理一个数"的代码——然后一次叫来 100 万个线程，每个线程执行一遍循环体，各自负责一个 i。这个"只写循环体、交给很多线程执行"的函数就叫 kernel，用 __global__ 标记：

__global__ void vecAdd(float* a, float* b, float* c) {
    int i = ???;          // 我是谁？我负责第几个数？
    c[i] = a[i] + b[i];
}

所有线程跑的是同一份代码，唯一不同的是 i。所以整件事的关键就是那个 ???：每个线程怎么算出自己的 i。Oxford lec1 第 22 页原话是代码要 "written from the point of view of a single thread"（从单个线程的角度来写）。

第二步：线程分三层——grid / block / thread（2026-11-10）

100 万个线程不是一盘散沙，CUDA 把它们分成三层（PG §1.2.2.1）：

层 是什么 编号 / 大小
grid（网格） 一次 kernel 启动的全部线程 里面有 gridDim.x 个 block
block（线程块） 一组线程；所有 block 一样大 自己的编号 blockIdx.x，从 0 到 gridDim.x - 1；每个 block 有 blockDim.x 个线程
thread（线程） 一个线程 在本 block 里的编号 threadIdx.x，从 0 到 blockDim.x - 1

类比：一所学校考试。

  • grid = 整所学校；
  • block = 一间教室，每间教室座位数一样（blockDim）；
  • thread = 一个座位上的考生；
  • blockIdx = 教室号，threadIdx = 座位号，两者都从 0 开始数。

为什么要分出"教室"这一层？ PG 原文：一个 block 的所有线程都放在同一个 SM（GPU 里的一个计算"车间"）上执行，所以同一个 block 的线程能用片上的 shared memory 交换数据、能互相等待；不同 block 之间则不行（第 2 章细讲）。现在只要记住：block 是"能互相配合的一组线程"。

启动时用 <<< >>> 说清楚分几间教室、每间几个座位（PG §2.1.2.2，叫 execution configuration，执行配置）：

vecAdd<<<4, 256>>>(a, b, c);
//       ↑   ↑
//       |   blockDim.x = 256：每个 block 256 个线程
//       gridDim.x = 4：一共 4 个 block
// 总线程数 = 4 × 256 = 1024

在 kernel 里面，这四个量都能直接读到：gridDim、blockDim（启动时给的尺寸）和 blockIdx、threadIdx（每个线程自己的编号）。它们其实各有 .x / .y / .z 三个分量（可以排成二维、三维），本章只用 .x，没写的维度默认是 1。

第三步：算出自己的全局编号（2026-11-10）

考生要从"教室号 + 座位号"算出全校唯一的准考证号：前面的教室全部坐满，一共 教室号 × 每间座位数 人，再加上自己的座位号。

\[i = \texttt{blockIdx.x} \times \texttt{blockDim.x} + \texttt{threadIdx.x}\]

读法：i 等于"block 编号乘 block 大小，再加线程在 block 里的编号"。

数字演示 1（PG §2.1.2.3 的例子）：<<<4, 256>>>，向量长 1024。

block blockIdx.x × 256 这个 block 的线程负责
0 0 元素 0–255（i 就等于 threadIdx.x）
1 256 元素 256–511
2 512 元素 512–767
3 768 元素 768–1023

数字演示 2（Oxford lec1 第 21 页）：4 个 block、每个 64 线程。第 1 号 block 里的第 44 号线程：

\[i = 1 \times 64 + 44 = 108\]

于是 kernel 补全成：

__global__ void vecAdd(float* a, float* b, float* c) {
    int i = blockIdx.x * blockDim.x + threadIdx.x;
    c[i] = a[i] + b[i];
}

每个线程算出不同的 i，1024 个线程正好把 0–1023 全覆盖、不重不漏。

第四步：n 不是整数倍怎么办——向上取整 + 越界检查（2026-11-10）

真实数据长度很少正好是 256 的倍数。比如 n = 1000，block 还是 256 个线程：

  1. host 端：block 数要向上取整。 1000 / 256 = 3.9，只开 3 个 block 只有 768 个线程，最后 232 个数没人算。所以要开 4 个：

$\(\texttt{gridDim.x} = \left\lceil \frac{n}{B} \right\rceil = \frac{n + B - 1}{B}\ \text{（整数除法）} = \frac{1000 + 255}{256} = 4\)$

(n + B - 1) / B 是 C/C++ 里向上取整的标准写法；Rust 里直接写 n.div_ceil(B)（本仓库 solutions/cubecl-lab/src/lib.rs 的 vec_add 就是这么写的）。

  1. kernel 端：多出来的线程要"举手不答题"。 4 × 256 = 1024 个线程，比 1000 多 24 个。编号 1000–1023 的线程如果照样执行 c[i] = a[i] + b[i]，就会读写数组外面的内存——轻则结果被污染，重则程序崩溃。所以加一行越界检查（PG §2.1.2.3.1 Bounds Checking）：

cpp __global__ void vecAdd(float* a, float* b, float* c, int n) { int i = blockIdx.x * blockDim.x + threadIdx.x; if (i < n) // 编号超出数据长度的线程什么也不做 c[i] = a[i] + b[i]; } // host 端 int B = 256; vecAdd<<<(n + B - 1) / B, B>>>(a, b, c, n);

这两件事永远成对出现：host 向上取整保证"人够"，kernel 越界检查保证"多的人不捣乱"。

顺带一句 block 大小怎么选：PG §1.2.2.2 建议 block 的线程数取 32 的倍数（128、256 最常见），因为硬件按 32 个线程一组（叫 warp）执行，不是 32 的倍数时最后一组会有空位。warp 是第 2 章的内容，这里先记住"取 32 的倍数"。

数学原理

  • 向上取整：\(\lceil n/B \rceil = \lfloor (n + B - 1)/B \rfloor\)。理由：设 \(n = qB + r\)（\(0 \le r < B\)）。\(r = 0\) 时加上 \(B-1\) 不够再进一位，结果是 \(q\)；\(r \ge 1\) 时 \(r + B - 1 \ge B\)，正好多进一位，结果是 \(q + 1\)。
  • 全局编号不重不漏：block \(b\) 覆盖区间 \([bB,\ bB + B - 1]\)，相邻 block 首尾相接，所以 \(\{bB + t \mid 0 \le b < G,\ 0 \le t < B\}\) 恰好是 \(0\) 到 \(GB - 1\) 每个整数各一次。这就是"二维编号（教室, 座位）→ 一维编号"的行优先展开，和二维数组 A[b][t] 存成一维 A[b*B + t] 是同一回事。

讲义 ↔ 代码：

讲义 公式 / 说法 写法 跑出来
第二、三步 <<<4, 256>>> \(i = b \times 256 + t\) launch_indices(4, 256)：广播出 4 × 256 的编号表 block 0–3 各管 0–255、256–511、512–767、768–1023
第三步 Oxford 例子 \(1 \times 64 + 44\) global_index(1, 64, 44) 108
第四步 向上取整 \(\lceil 1000 / 256 \rceil\) ceil_div(1000, 256)，即 (n + B - 1) // B 4；开 1024 个线程，24 个越界
第四步 越界检查 if (i < n) vec_add(a, b, 256)：先 i = i[i < n] 再加 和 a + b 一样；去掉检查 → IndexError

关键几行：

block_idx = np.arange(grid_dim)[:, None]   # 每一行是一个 block（教室号）
thread_idx = np.arange(block_dim)[None, :]  # 每一列是一个座位号
i = block_idx * block_dim + thread_idx      # 广播：一次算出所有线程的 i
grid = (n + B - 1) // B                     # host：向上取整，保证"人够"
i = i[i < n]                                # kernel：多的人举手不答题
c[i] = a[i] + b[i]

代码里才看得到的 3 件事：

  1. "一次启动所有线程"在代码里就是一次广播：launch_indices 返回一张 grid × block 的表，第 b 行第 t 列就是 blockIdx.x = b、threadIdx.x = t 的那个线程算出的 i。GPU 上这些线程真的同时跑，NumPy 只是一次算完整张表。
  2. 越界在 NumPy 里会报错，在 GPU 上不会：去掉越界检查时 NumPy 抛 IndexError；GPU 上没有这层保护，越界读写会悄悄碰到别的内存（第 4 章用 compute-sanitizer 查）。
  3. Python 的 // 是向下取整：1000 // 256 是 3，所以向上取整要写成 (n + B - 1) // B，和 C++ 的整数除法同一个套路。
