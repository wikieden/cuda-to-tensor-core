本章缩写：exp = exponential（指数函数 \(e^x\)）· CE = Cross Entropy（交叉熵）· LSE = Log-Sum-Exp（对数 / 求和 / 指数：\(\log \sum e^{x_i}\)）

讲解

第一步：softmax 与"减最大值"（2026-11-14）

\[\text{softmax}(x)_i = \frac{e^{x_i}}{\sum_j e^{x_j}}\]

直接算有溢出问题：\(x = 100\) 时 \(e^{100} \approx 2.7 \times 10^{43}\)，超过 FP16（最大约 65504），甚至接近 FP32 的上限之外的危险区。标准做法是先减去最大值 \(m = \max_j x_j\)：

\[\text{softmax}(x)_i = \frac{e^{x_i - m}}{\sum_j e^{x_j - m}}\]

分子分母同乘 \(e^{-m}\)，结果不变；但现在所有指数都 ≤ 0，\(e^{x_i - m} \in (0, 1]\)，不会溢出。

第二步：标准写法读三遍（2026-11-14）

对一行长度 N 的数据：

  1. 读一遍，求最大值 \(m\)；
  2. 读一遍，求分母 \(\ell = \sum_j e^{x_j - m}\)；
  3. 读一遍，算 \(e^{x_i - m} / \ell\) 并写出。

softmax 每个元素只做几次运算，是典型的 memory-bound（第 9 章）——时间几乎就是读写显存的次数。三遍读 + 一遍写 = 4 次访存。行太长放不进 shared memory 时，每一遍都要回显存。

第三步：online softmax——边走边改账（2026-11-14）

能不能把第 1、2 遍合成一遍？难点是：算分母时需要最终的最大值 \(m\)，但读到一半时还不知道后面有没有更大的。

关键观察：如果之前用的是"旧的最大值" \(m_{\text{old}}\)，后来发现更大的 \(m_{\text{new}}\)，那么之前累加的每一项都只差一个公共因子：

\[e^{x_j - m_{\text{new}}} = e^{x_j - m_{\text{old}}} \cdot e^{m_{\text{old}} - m_{\text{new}}}\]

所以只要把已经累加的和整体乘上 \(e^{m_{\text{old}} - m_{\text{new}}}\) 就能修正。一边读一边维护 \((m, \ell)\)：

m = -∞, ℓ = 0
for x in 这一行:
    m_new = max(m, x)
    ℓ = ℓ * exp(m - m_new) + exp(x - m_new)    # 旧账按新基准打折，再加上新项
    m = m_new

数字演示：\(x = [1, 3, 2]\)。

读到 m ℓ
1 1 \(e^{0} = 1\)
3 3 \(1 \cdot e^{1-3} + e^{0} = 0.1353 + 1 = 1.1353\)
2 3 \(1.1353 \cdot e^{0} + e^{2-3} = 1.1353 + 0.3679 = 1.5032\)

直接算：\(e^{1-3} + e^{3-3} + e^{2-3} = 0.1353 + 1 + 0.3679 = 1.5032\) ✓。

现在 softmax 只要两遍：一遍得到 \((m, \ell)\)，一遍输出。访存从 4 次变 3 次。

更重要的是这个 \((m, \ell)\) 可以分块合并：两块各自算出 \((m_1, \ell_1)\)、\((m_2, \ell_2)\)，合并为

\[m = \max(m_1, m_2), \quad \ell = \ell_1 e^{m_1 - m} + \ell_2 e^{m_2 - m}\]

——满足结合律，所以可以并行归约（第 10–11 章：先线程内、再 warp shuffle、再 block）。FlashAttention-2 论文 §2.3.1 把同样的技巧扩展到"连同输出 \(O\) 一起打折修正"，这就是 FlashAttention 的核心（下一章）。

第四步：算子融合——中间结果别落地（2026-11-14）

融合（fusion）：把几个连着的运算写进同一个 kernel，中间结果留在寄存器 / shared memory 里，不写回显存。

数字演示：对一个 1 亿元素的 BF16 张量做 y = gelu(x + bias)。

写法 显存访问 字节数
两个 kernel：t = x + bias，y = gelu(t) 读 x、写 t、读 t、写 y 4 × 200 MB = 800 MB
一个融合 kernel 读 x、写 y 2 × 200 MB = 400 MB

两者都是 memory-bound，融合后耗时约为一半。还省掉了一次 kernel 启动（第 26 章）。

AI 训练 / 推理里最有价值的融合：

融合 省掉了什么 代表实现
残差加 + RMSNorm / LayerNorm 一次完整读写 Quack、Liger、Apex
GEMM + bias + 激活（epilogue 融合） GEMM 输出的一次读写 cuBLASLt、CUTLASS epilogue（第 15、20 章）
QKᵀ → softmax → PV（attention） \(N \times N\) 的中间矩阵 FlashAttention（第 22 章）
最后一层 Linear + 交叉熵 词表大小 × token 数的 logits（可能几十 GB） Liger 的 fused linear cross entropy：分块算、算完即丢
量化 + GEMM 反量化后的大矩阵 Marlin、DeepGEMM

torch.compile 的 Inductor 会自动做一部分逐元素融合；跨 GEMM 的融合（如 attention）还是要靠手写 kernel。

第五步：memory-bound kernel 做到"光速"（2026-11-14）

Quack 博客的结论：RMSNorm、softmax、交叉熵这类 kernel 要达到显存带宽上限（SOL），两件事最关键——

  1. 全局内存合并读写（第 6 章；向量化读）；
  2. 按归约维度大小选归约策略：一行很短 → 一个 warp 处理一行，只用 shuffle；一行中等 → 一个 block 一行，warp + shared；一行很长（几万到几十万，比如大词表的交叉熵）→ 一个 cluster 处理一行，用分布式 shared memory 归约（第 17 章）。

Quack 报告它的归约模板在 H100 上对 256 到 262k 的各种行长都接近带宽上限（04 调研 摘录）。

Transformer 讲义 里 softmax 一章 本仓库 softmax 本身的数学含义

数学原理

  • 平移不变性：\(\text{softmax}(x + c) = \text{softmax}(x)\)，所以可以减 \(m\)。
  • online 更新的正确性：归纳假设 \(\ell = \sum_{j \le k} e^{x_j - m}\)，读入 \(x_{k+1}\)、\(m' = \max(m, x_{k+1})\) 后 \(\ell e^{m - m'} + e^{x_{k+1} - m'} = \sum_{j \le k+1} e^{x_j - m'}\)。
  • 合并的结合律：\((m, \ell)\) 实际表示 \(\log\)-域里的 \(\text{LSE} = m + \log \ell\)；合并就是 \(\text{LSE}(a \cup b) = \log(e^{\text{LSE}_a} + e^{\text{LSE}_b})\)，显然满足结合律和交换律。
  • 融合的收益：memory-bound 时耗时 ∝ 总访存字节；融合把中间张量的"一写一读"去掉。

关键几行：

m, l = -math.inf, 0.0
for x in xs:
    m_new = max(m, x)
    l = l * math.exp(m - m_new) + math.exp(x - m_new)   # 旧账打折 + 新项
    m = m_new

def merge(a, b):                                        # 两块的 (m, ℓ) 合并
    m = max(a[0], b[0])
    return m, a[1] * math.exp(a[0] - m) + b[1] * math.exp(b[0] - m)

代码里才看得到的 3 件事：

  1. math.exp(-math.inf) 等于 0：所以第一次循环时 l * exp(m - m_new) 自动是 0，不用单独写"第一次"的分支。
  2. 溢出时 NumPy 给的是 inf 和 nan，不报错：softmax_naive 在 FP16 下得到 [nan nan nan]（inf ÷ inf）；代码用 np.errstate 把警告关掉了，GPU 上同样是悄悄变成 nan。
  3. merge 满足结合律：merge(merge(a, b), c) == merge(a, merge(b, c))，所以能按任意分组并行归约（第 10–11 章）。
