第 14 章 · SGEMM ②：寄存器分块、向量化与 warptiling

▶ 打开本章可交互动画

本章回答：为什么"一个线程算 C 的 64 个元素"比"一个线程算 1 个"快 5 倍？外积（outer product）的写法是什么？向量化读、转置 As、调参、warptiling 各贡献了多少？从 13% 到 94% 的每一步在优化什么？
讲解日期：2026-11-14 · 上一章：第 13 章 SGEMM ① · 下一章：第 15 章 Tensor Core
对应原文：Boehm worklog Kernel 4–10（materials/text/blog-boehm-cuda-matmul-worklog.txt 第 383–806 行）；Gordić《Inside NVIDIA GPUs》warp-tiling 部分（text/blog-gordic-inside-nvidia-gpus-matmul.txt）；CUTLASS 的分层 GEMM 概念（code/cutlass/cpp-docs/）

本章缩写：TM / TN = Thread tile 在 M / N 方向的大小（每个线程算 TM × TN 个结果）· WM / WN = Warp tile 大小 · LDS = LoaD Shared（从 shared memory 读的 SASS 指令；LDS.128 = 一次读 128 位）· ILP = Instruction-Level Parallelism（指令级并行）

讲解

第一步：Kernel 3 的瓶颈——每次乘加读两次 shared（2026-11-14）

第 13 章结尾说了：Kernel 3 里每个线程算 C 的 1 个元素，内循环每做 1 次乘加，要读 2 次 shared memory。shared memory 再快，访存指令也要占发射槽；计算单元大部分时间在等。

办法和第 13 章一样："读一次、用多次"，只是这次从 shared 读到寄存器后，在寄存器里多次使用。要做到这一点，一个线程就得负责多个 C 元素。

第二步：Kernel 4——一个线程算一列 8 个（2026-11-14）

每个线程算 C 的 TM = 8 个（同一列、相邻 8 行）。内循环：

float threadResults[TM] = {0.0};                     // 8 个累加器，放寄存器
for (uint dotIdx = 0; dotIdx < BK; ++dotIdx) {
    float Btmp = Bs[dotIdx * BN + threadCol];        // B 的这个数，8 个结果都要用 → 读一次放寄存器
    for (uint resIdx = 0; resIdx < TM; ++resIdx)
        threadResults[resIdx] += As[(threadRow * TM + resIdx) * BK + dotIdx] * Btmp;
}

每读 1 次 Bs 用 8 次。shared 读次数从"每次乘加 2 次"变成"每 8 次乘加 9 次"。

结果：8475 GFLOP/s（36.5%），比 Kernel 3 快 2.8 倍。

第三步：Kernel 5——一个线程算 8 × 8 的方块（外积）（2026-11-14）

再进一步：每个线程算 C 的一个 TM × TN = 8 × 8 = 64 个元素的小方块。

关键是把循环顺序换成外积形式：对每个 dotIdx（K 方向的一步），

  1. 从 As 读 A 的一小列 8 个数到寄存器 regM[8]；
  2. 从 Bs 读 B 的一小行 8 个数到寄存器 regN[8]；
  3. 做 8 × 8 = 64 次乘加：threadResults[m][n] += regM[m] * regN[n]。
for (uint dotIdx = 0; dotIdx < BK; ++dotIdx) {
    for (uint i = 0; i < TM; ++i) regM[i] = As[(threadRow * TM + i) * BK + dotIdx];
    for (uint i = 0; i < TN; ++i) regN[i] = Bs[dotIdx * BN + threadCol * TN + i];
    for (uint m = 0; m < TM; ++m)
        for (uint n = 0; n < TN; ++n)
            threadResults[m * TN + n] += regM[m] * regN[n];
}

为什么方块比一列好？ 算 \(T_M \times T_N\) 个结果，每一步要读 \(T_M + T_N\) 个数：

每线程算 每步读 shared 每步乘加 乘加 ÷ 读
1 × 1（Kernel 3） 2 1 0.5
8 × 1（Kernel 4） 9 8 0.89
8 × 8（Kernel 5） 16 64 4

周长相同时，正方形面积最大——读的是"边"，算的是"面积"。Boehm 原话："It's more efficient to calculate a square of results per thread than a column of results because we can share more of the inputs."

Kernel 5 的配置：block tile BM = BN = 128、BK = 8，每个 block 256 个线程，每个线程 64 个结果（256 × 64 = 128 × 128 ✓）。

结果：15972 GFLOP/s（68.7%），又快一倍。

代价：每个线程光累加器就要 64 个寄存器，加上 regM、regN 等，寄存器用量大，occupancy 很低——但正如第 8 章所说，这里靠 ILP（一个线程同时有 64 个互不依赖的乘加）隐藏延迟，不需要高 occupancy。

第四步：Kernel 6–9——向量化与调参（2026-11-14）

  • Kernel 6 · 向量化（18237 GFLOP/s，78.4%）：
  • 把 As 转置存进 shared（A 的一小列变成连续的一行），这样读 regM 也能用 128 位的 LDS.128 一次读 4 个（Bs 本来就是连续的）；
  • 显存读写全部用 float4（第 6 章第四步），配合对齐保证让编译器生成 LDG.128。
  • Kernel 7–8：Boehm 尝试消除 shared memory 的 bank conflict，冲突是没了，整体却更慢，所以博客里跳过。
  • Kernel 9 · 自动调参（19721 GFLOP/s，84.8%）：BM、BN、BK、TM、TN 这些参数组合起来几百种，写脚本全部试一遍。A6000 上 BM=BN=128, BK=16, TM=TN=8 最好；A100 上最优的却是 BM=BN=64, BK=16, TM=TN=4——换一张卡，最优参数就变。这就是为什么 Triton 有 @autotune、CUTLASS 有 profiler（04 调研 §5.4）。

第五步：Kernel 10——warptiling，把 warp 这一层显式化（2026-11-14）

到目前为止的层次是 block tile → thread tile，warp 这一层是隐式的。Kernel 10 在中间加一层 warp tile：一个 warp 负责 block tile 里的一块（比如 64 × 32），warp 里的 32 个线程再分这一块。

Boehm 列出的三层并行：

层 并行在哪里
block tile 不同 block 在不同 SM 上
warp tile 不同 warp 在不同 warp 调度器上
thread tile 同一线程的多条独立指令（ILP）

好处：

  1. bank conflict 只发生在同一个 warp 内（第 7 章），按 warp 规划 shared memory 的读取模式更容易控制冲突；
  2. 同一 warp 的线程读的数据更集中，寄存器缓存局部性更好；
  3. 最重要的：warp tile 正好对应 Tensor Core 的工作方式——Tensor Core 指令是"一个 warp 合作算一个小矩阵乘"（下一章）。Boehm 代码里的注释："Later this will map well to warp-wide matrix instructions, executed on tensor cores."

结果：21779 GFLOP/s（93.7%）。

一条主线贯穿始终：每一层存储（显存 → shared → 寄存器）都做一次分块，让上一层读来的数据在下一层被尽量多次地复用。这正是 CUTLASS 的分层结构：threadblock tile → warp tile → thread（或 MMA）tile。

这些都还是 FP32 的 CUDA core 计算。A6000 的 Tensor Core 做 TF32 / BF16 快 2.5–3.5 倍（Boehm 第 21 行），下一章开始用 Tensor Core。

口诀

每一层都分块：显存到 shared 一次，shared 到寄存器一次；
一人算一格读两次，一人算一方块读一圈：读的是边，算的是面积；
外积：读一列 A、一行 B，乘出一个小方块；
读宽一点（float4、LDS.128），参数自动调，换卡就重调；
中间加一层 warp tile，正好接上 Tensor Core。

数学原理

  • 线程级算术强度：每个 K 步，读 shared \(T_M + T_N\) 个数，做 \(T_M T_N\) 次乘加。比值 \(\frac{T_M T_N}{T_M + T_N}\) 在 \(T_M T_N\) 固定时于 \(T_M = T_N\) 取最大（均值不等式）。
  • block 级算术强度（对显存）：block tile \(B_M \times B_N\)，每个 K 步读 \((B_M + B_N) B_K\) 个数，做 \(B_M B_N B_K\) 次乘加；FP32 下强度 \(= \frac{2 B_M B_N B_K}{4 (B_M + B_N) B_K} = \frac{B_M B_N}{2(B_M + B_N)}\)。\(B_M = B_N = 128\) 时为 32 FLOP/byte，接近 A6000 的脊点 39。
  • 寄存器预算：\(T_M T_N + T_M + T_N\) 个 float 至少要这么多寄存器，8 × 8 时 80 个。

关键几行：

acc = np.zeros((tm, tn))                      # threadResults，放寄存器
for dot in range(BK):
    reg_m = As[row * tm:(row + 1) * tm, dot]  # 从 shared 读一小列 A（TM 个）
    reg_n = Bs[dot, col * tn:(col + 1) * tn]  # 从 shared 读一小行 B（TN 个）
    acc += np.outer(reg_m, reg_n)             # 外积：TM × TN 次乘加

代码里才看得到的 3 件事：

  1. np.outer 就是外积：一列 × 一行得到一个小方块，正是 Kernel 5 内循环那两层 for m / for n。
  2. 1 × 1 时读 2 次而不是 1 + 1 次：公式 \(T_M + T_N\) 在 1 × 1 时正好也是 2，和 Kernel 3 一样。
  3. block_tile 把 256 个线程排成 16 × 16：每个线程 (r, c) 负责结果的第 r 块行、第 c 块列；拼起来就是整个 128 × 128。

自己改一改（不影响练习答案）：

  • 把 block_tile(As, Bs) 的 tm、tn 换成 8 × 4、4 × 8，确认结果仍和 As @ Bs 一致。
  • 把 As 的 BK 从 8 改成 16（Kernel 9 在 A6000 上的最优值），确认结果不变。
