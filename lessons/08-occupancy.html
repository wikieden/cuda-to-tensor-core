本章缩写：CC = Compute Capability（计算能力，架构版本号）· ILP = Instruction-Level Parallelism（指令级 / 并行：一个线程内多条互不依赖的指令同时在路上）

讲解

第一步：等的时候换人干——延迟隐藏（2026-11-14）

Best Practices §11.1 开头一句话说透了：

线程里的指令是按顺序执行的，所以一个 warp 卡住时，换别的 warp 来执行，是隐藏延迟、让硬件保持忙碌的唯一办法。

类比：洗衣房。 一台洗衣机（SM 的计算单元）洗一桶要 40 分钟（显存延迟），但往里放衣服只要 1 分钟（发一条指令）。只有一个人用，洗衣机 40 分钟里 39 分钟在等；有 40 个人轮流用，每分钟都有人在放衣服——机器一直在转。

GPU 正是这样：第 2 章说过 warp 切换零开销（寄存器一直留在片上）。每个周期，warp 调度器挑一个"下一条指令准备好了"的 warp 发射。一个 SM 同时驻留很多 warp，就总能挑到一个能干活的。

Gordić 的数字（H100）：一个 SM 每周期最多从 4 个 warp 发射指令（4 个象限各一个调度器），也就是同一时刻真正并行的只有 128 个线程；但一个 SM 能驻留 2048 个线程（64 个 warp）。多出来的 60 个 warp 不是拿来"同时算"的，是拿来轮流等的。

第二步：occupancy 的定义（2026-11-14）

PG §2.3.7：

\[\text{occupancy} = \frac{\text{SM 上实际驻留的 warp 数}}{\text{SM 最多能驻留的 warp 数}}\]

H100 / B200（CC 9.0 / 10.0）每个 SM 最多 64 个 warp（2048 个线程）。

一个 SM 能放几个 block，取决于四道门槛里最紧的那一道：

门槛 CC 10.0 的上限（PG 表 2） 一个 block 用多少
① 线程数 每 SM 2048 block 大小
② block 数 每 SM 32 1
③ 寄存器 每 SM 65536 个 每线程寄存器数 × block 大小
④ shared memory 每 SM 233472 字节（228 KB） 每 block 用的字节数

第三步：照着 PG 算三个例子（2026-11-14）

例 1：block 太大（PG 原例）。<<<512, 768>>>：每个 block 768 个线程。线程门槛：2048 / 768 = 2.67 → 2 个 block，驻留 1536 个线程。

\[\text{occupancy} = \frac{2 \times 768}{2048} = 75\%\]

例 2：block 太小（PG 原例）。<<<512, 32>>>：每个 block 只有 32 个线程。线程门槛允许 64 个 block，但 block 门槛只允许 32 个 → 32 × 32 = 1024 个线程。

\[\text{occupancy} = \frac{1024}{2048} = 50\%\]

例 3：shared memory 卡住（PG 原例）。每个 block 用 100 KB shared memory：第 3 个 block 需要 300 KB，超过 228 KB → 只能放 2 个 block。block 只有 128 个线程的话，occupancy = 256 / 2048 = 12.5%。

例 4：寄存器卡住（Best Practices §11.1.1）。CC 7.0，每线程 37 个寄存器，block 128 个线程。寄存器按 warp 分配、向上取整到 256 的倍数：37 × 32 = 1184 → 1280 个 / warp。每个 block 4 个 warp = 5120 个寄存器，65536 / 5120 = 12.8 → 12 个 block = 48 个 warp。

\[\text{occupancy} = 48 / 64 = 75\%\]

想要 100% occupancy，每线程最多只能用 65536 / 2048 = 32 个寄存器。

第四步：occupancy 不是越高越好（2026-11-14）

Best Practices §11.1 原话："Higher occupancy does not always equate to higher performance……However, low occupancy always interferes with the ability to hide memory latency."——太低一定不好，但高到一定程度后再高就没用了。

原因是还有第二种隐藏延迟的办法：让一个线程自己同时有好几件事在路上（ILP）。

// 低 ILP：每次读都要等上一次算完
for (k...) acc += a[k] * b[k];

// 高 ILP：一个线程同时发出 4 次读，再一起算
float x0 = a[k], x1 = a[k+1], x2 = a[k+2], x3 = a[k+3];   // 4 次读同时在路上
acc0 += x0 * ...; acc1 += x1 * ...; ...

高性能 GEMM 的典型做法正好相反于"高 occupancy"：每个线程用大量寄存器存一大块结果（第 14 章的寄存器分块），occupancy 可能只有 12–25%，但每个 warp 内部的并行度很高，照样把计算单元喂饱。FlashAttention-3、CUTLASS 的 Hopper kernel 每个 SM 常常只放 1 个 block。

所以 occupancy 是一个诊断指标：kernel 慢、Nsight Compute 显示大量 warp 在等显存（stall long scoreboard）、occupancy 又很低时，才考虑提高它。

第五步：能调的旋钮（2026-11-14）

旋钮 做法 代价
block 大小 128 / 256 常是好起点；配合 occupancy 计算 —
寄存器 __launch_bounds__(maxThreads, minBlocks) 或 -maxrregcount 限制 用超了会 spill 到 local memory（在显存里，第 5 章）
shared memory 减小 tile；或用动态 shared 按需申请 tile 小了复用就少
让程序自己选 cudaOccupancyMaxPotentialBlockSize、cudaOccupancyMaxActiveBlocksPerMultiprocessor —
查看 nvcc --resource-usage；Nsight Compute 的 Occupancy 小节和计算器 —

Best Practices 还建议总是写单参数的 __launch_bounds__(maxThreadsPerBlock)：告诉编译器最多会用多大的 block，避免它给每个线程分太多寄存器，导致"too many resources requested for launch"。

数学原理

  • 每 SM 能放的 block 数 \(= \min\left(\left\lfloor \frac{T_{\max}}{T} \right\rfloor, B_{\max}, \left\lfloor \frac{R_{\max}}{R_{\text{block}}} \right\rfloor, \left\lfloor \frac{S_{\max}}{S_{\text{block}}} \right\rfloor\right)\)；寄存器按 warp 粒度取整，\(R_{\text{block}} = \lceil T/32 \rceil \cdot \lceil 32R / 256 \rceil \cdot 256\)。
  • Little 定律（排队论）：要让带宽打满，同时在路上的请求数 = 带宽 × 延迟。例：延迟 600 周期、每周期要发 4 个请求才能打满，就需要约 2400 个请求同时在路上——由"驻留 warp 数 × 每个 warp 在路上的请求数"共同提供，这就是 TLP 和 ILP 可以互相替代的原因。

关键几行：

per_warp = math.ceil(regs * 32 / 256) * 256        # 寄存器按 warp 分配，取整到 256
gates = {"threads": 2048 // threads, "blocks": 32,
         "regs": 65536 // (warps * per_warp),
         "smem": 233472 // smem_bytes}
worst = min(gates, key=gates.get)                  # 最紧的那道门槛
occ = gates[worst] * math.ceil(threads / 32) / 64  # 驻留 warp ÷ 最多 warp

代码里才看得到的 3 件事：

  1. 寄存器要按 warp 取整：例 4 如果直接算 65536 / (37 × 128) = 13.8，会得到 13 个 block；按 warp 取整到 256 后才是 12 个。函数里的 round_to_256 参数可以关掉取整，对比两种算法。
  2. shared 的上限用字节：228 KB = 233472 字节；真实硬件每个 block 还会额外占 1 KB 系统保留的 shared（PG 表里有），这里和讲义一样忽略。
  3. occupancy 只是理论值：Nsight Compute 里还有"实测 occupancy"，会因为尾部效应、block 提前退出而更低（第 9 章）。
