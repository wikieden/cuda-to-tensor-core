编程模型

C01 · 一次 kernel 启动里，线程分成哪三层？<<<A, B>>> 里的 A、B 各是什么？

来源：第 1 章 · 加入 2026-11-10 · 复习记录：

答案

grid（整次启动）→ block（一组线程）→ thread（一个线程）。所有 block 一样大。

kernel<<<A, B>>>(...)：A = gridDim，grid 里有几个 block；B = blockDim，每个 block 有几个线程。总线程数 = A × B。

类比：考场。grid = 整个学校，block = 教室，thread = 座位；每间教室座位数一样。

C02 · 一维情况下，线程的全局编号公式是什么？blockDim.x = 64、blockIdx.x = 1、threadIdx.x = 44 时等于几？

来源：第 1 章 · 加入 2026-11-10 · 复习记录：

答案

i = blockIdx.x * blockDim.x + threadIdx.x

= 1 × 64 + 44 = 108（Oxford lec1 第 21 页的例子）。

读法：前面的教室（block）全部坐满，一共 blockIdx.x × blockDim.x 个人，再加上自己在本教室的座位号。

C03 · 数据长度 n 不是 block 大小 B 的整数倍时，host 和 kernel 各要做哪件事？

来源：第 1 章 · 加入 2026-11-10 · 复习记录：

答案
  • host：block 数用向上取整 (n + B - 1) / B（Rust 里是 n.div_ceil(B)），保证线程够用；
  • kernel：加越界检查 if (i < n)，多出来的线程什么也不做，否则会读写数组外的内存。

例：n = 1000，B = 256 → 4 个 block，1024 个线程，最后 24 个线程空转。

C04 · block 是怎么被派到 SM 上的？为什么同一个 grid 里的 block 之间不能互相等？

来源：第 2 章 · 加入 2026-11-14 · 复习记录：

答案
  • 调度器看哪个 SM 还有空位（寄存器、shared、线程数都够）就派过去；派到哪、按什么顺序，程序既不能控制也不能查询；
  • 一个 block 派给某个 SM 后就在那里跑到结束；
  • 规矩：block 必须能以任意顺序、并行或串行执行。如果 block 7 等 block 900，而 900 还没被派出去、7 又占着位置不走，就死锁。

换来的好处：同一程序在任何 SM 数的 GPU 上都对。block 间要交换数据：拆成两个 kernel、原子操作、或用 cluster。

C05 · 什么是 wave（波）和尾部效应？H100 上 grid 从 132 个 block 变成 133 个会怎样？

来源：第 2 章 · 加入 2026-11-14 · 复习记录：

答案

一次能同时跑的 block 数 = SM 数 × 每 SM 能放的 block 数，叫一波。波数 = ⌈block 数 / 一波的量⌉；最后一波不满时，那段时间部分 SM 闲着，叫尾部效应。

H100 132 个 SM、每 SM 放 1 个大 block：132 个 → 1 波、100%；133 个 → 2 波，利用率 133 / 264 ≈ 50%，耗时几乎翻倍。经验：block 数要是 SM 数的好几倍；GEMM 用 persistent kernel / Stream-K 对付尾部。

C06 · warp 是什么？SIMT 和 CPU 的 SIMD 有什么区别？

来源：第 3 章 · 加入 2026-11-14 · 复习记录：

答案

warp = 32 个线程一组，硬件每次给一个 warp 发一条指令，32 个线程各用自己的数据执行（SIMT：Single Instruction, Multiple Threads）。

区别（PG §3.2.2.1）：SIMD 把向量宽度暴露给程序员，要自己装向量、自己处理掩码；SIMT 让你写标量的单线程代码，每个线程可以有自己的分支，由硬件捆起来执行、处理分岔。写对程序时可以不管 warp，想跑快必须管。

C07 · 一个 warp 里一半线程走 if、一半走 else，会发生什么？怎么避免？

来源：第 3 章 · 加入 2026-11-14 · 复习记录：

答案

warp divergence：warp 把每条走到的分支都执行一遍，执行某条分支时不走这条路的 lane 被屏蔽、原地等。两条各耗时 10 的分支总共耗时 20，lane 利用率 50%。

分岔只发生在 warp 内部：让分支条件以 warp 为单位一致（如按 threadIdx.x / 32 分），就没有浪费。block 大小取 32 的倍数，避免最后一个 warp 有空 lane。

C08 · 为什么老代码里"warp 内 32 个线程永远齐步走"的假设在新 GPU 上会出错？

来源：第 3 章 · 加入 2026-11-14 · 复习记录：

答案

CC 7.0（Volta）起是独立线程调度：每个线程有自己的程序计数器和调用栈，warp 内可以更细粒度地分开、汇合。依赖隐式齐步走的代码（如不加同步的 warp 内归约）可能算错。

改法：需要 warp 内同步时显式 __syncwarp()，或用带 _sync 后缀、带 mask 的 warp 函数（__shfl_down_sync 等）。

C09 · 一个完整 CUDA 程序的五步，各用什么 API？

来源：第 4 章 · 加入 2026-11-14 · 复习记录：

答案

① 分配：cudaMalloc（显存）、cudaMallocHost（锁页 host 内存）； ② 拷进：cudaMemcpy(dst, src, bytes, cudaMemcpyDefault)（H2D）； ③ 启动：kernel<<<blocks, threads>>>(...)； ④ 同步并拷回：cudaDeviceSynchronize()、cudaMemcpy（D2H）； ⑤ 释放：cudaFree / cudaFreeHost。

PCIe 比显存窄几十倍：数据尽量一次运过去、在 GPU 上多做几道。

C10 · kernel 启动后 CPU 会等吗？cudaGetLastError() 返回成功说明什么？

来源：第 4 章 · 加入 2026-11-14 · 复习记录：

答案

不等。启动是异步的（"下单"），CPU 立刻往下走；要结果或用 CPU 计时器测时间，必须先 cudaDeviceSynchronize()。

<<< >>> 不返回错误码，启动后要调 cudaGetLastError()；它返回成功只说明启动参数没问题，不代表 kernel 跑成功。kernel 运行中的错误（如越界）会在之后某个同步点冒出来；调试时在 kernel 后加 cudaDeviceSynchronize() 再查，或用 compute-sanitizer。

内存与性能分析

C11 · GPU 的五层内存各是什么、作用域是谁、谁来管？

来源：第 5 章 · 加入 2026-11-14 · 复习记录：

答案
层 作用域 谁管
寄存器 单个线程 编译器
shared memory 一个 block（cluster 内可跨 block） 你
L1 一个 SM 硬件
L2 全 GPU 硬件
显存（global） 所有线程 + host 你（分配、拷贝、访问模式）

每往外一层，延迟约高一个数量级、容量大一到两个数量级。H100：每 SM 寄存器 256 KB、shared + L1 共 256 KB（shared 最多 228 KB）、L2 50 MB、HBM3 80 GB。优化一句话：读一次、用很多次。

C12 · local memory 在哪里？什么情况下变量会被放进 local memory？

来源：第 5 章 · 加入 2026-11-14 · 复习记录：

答案

物理上在显存里（"local"指只有本线程可见，不是指位置），延迟和带宽同 global memory。

三种情况：① 数组下标编译时确定不了；② 结构体 / 数组太大，寄存器放不下；③ 寄存器用超了（spill）。用 nvcc -Xptxas -v 查寄存器数和 spill。

C13 · 什么是合并访存？一个 warp 每线程读 4 字节，四种情况各搬几箱？

来源：第 6 章 · 加入 2026-11-14 · 复习记录：

答案

显存按 32 字节一箱（sector） 读写；一个 warp 的 32 个请求被合并，落在同一箱的只运一次。利用率 = 用到的字节 ÷ 搬来的字节。

访问 箱数 利用率
a[i] 相邻 4 100%
a[i+1] 错位 5 80%
a[2i] 跨步 2 8 50%
间隔 ≥ 32 字节 32 12.5%

跨步 s（≤ 8）：4s 箱，利用率 1/s。地址顺序打乱不影响，只看落在几箱。

C14 · 二维数组怎么写才能合并访存？矩阵转置为什么要经过 shared memory？

来源：第 6 章 · 加入 2026-11-14 · 复习记录：

答案

让 threadIdx.x 对应内存里变化最快的那一维（行优先数组的列号）：col = blockIdx.x * blockDim.x + threadIdx.x，访问 A[row * N + col]。

转置 out[c][r] = in[r][c]：读按行合并，写就必然按列（或反过来）。办法：按行读进 shared memory → 同步 → 在 shared 里按列读 → 按行写出去，两头都合并。

C15 · __syncthreads() 的两条铁律是什么？

来源：第 7 章 · 加入 2026-11-14 · 复习记录：

答案
  1. "写完再读"之间要一道栅栏；循环里反复用同一块 shared memory 时，"读完再覆盖"之间也要一道。
  2. 必须被 block 里所有线程走到；写在只有部分线程能进的 if 里是未定义行为，常见结果是死锁。

C16 · shared memory 的 bank 怎么映射？什么叫 n 路 bank conflict？跨步访问冲突几路？

来源：第 7 章 · 加入 2026-11-14 · 复习记录：

答案

32 个 bank，每个 4 字节；字地址 w（字节地址 ÷ 4）在 bank w % 32。一个 warp 里多个线程访问同一 bank 的不同地址要排队，最多排几个就是几路冲突、耗时几倍；访问同一地址是广播，不冲突。

线程 t 读 s[t * stride]：冲突路数 = gcd(stride, 32)。奇数跨步永远不冲突。

C17 · __shared__ float tile[32][32] 按列读为什么最慢？怎么修？

来源：第 7 章 · 加入 2026-11-14 · 复习记录：

答案

tile[r][c] 的字地址 r·32 + c，bank = c：一整列都在同一个 bank，32 路冲突。

改成 tile[32][33]（每行多 1 个 padding）：bank = (r·33 + c) % 32 = (r + c) % 32，同一列的 32 个 r 落在 32 个不同 bank，无冲突，只多用 3% 空间。Tensor Core 时代常用 swizzle（地址异或）代替 padding。

C18 · occupancy 的定义？一个 SM 能放几个 block 由哪四道门槛决定？

来源：第 8 章 · 加入 2026-11-14 · 复习记录：

答案

occupancy = SM 上驻留的 warp 数 ÷ 最多能驻留的 warp 数（H100 / B200 为 64）。

四道门槛取最紧的：线程数（每 SM 2048）、block 数（32）、寄存器（65536，按 warp 以 256 为单位取整）、shared memory（228 KB）。

PG 例：768 线程 / block → 只能放 2 个 → 75%；32 线程 / block → 被 32 个 block 上限卡住 → 50%。想要 100%，每线程最多 32 个寄存器。

C19 · GPU 怎么隐藏显存延迟？occupancy 是不是越高越好？

来源：第 8 章 · 加入 2026-11-14 · 复习记录：

答案

两种办法：① 多 warp 轮流（TLP）：warp 切换零开销，一个在等显存就换另一个；② 单线程多件事在路上（ILP）：一个线程同时发出多次互不依赖的读或运算。

不是越高越好：太低一定不好，但 GEMM 这类 kernel 常常 occupancy 只有 12–25%，靠每线程的大寄存器 tile（ILP）照样跑满。occupancy 是诊断指标：慢、warp 都在等显存、occupancy 又低时才去提它。

C20 · roofline 公式是什么？H100 BF16 的脊点约多少？向量加法和大矩阵乘各落在哪？

来源：第 9 章 · 加入 2026-11-14 · 复习记录：

答案

可达性能 = min(峰值算力, 算术强度 × 显存带宽)，算术强度 = FLOP ÷ 读写字节；脊点 = 峰值 ÷ 带宽。

H100 BF16 ≈ 989 TFLOP/s ÷ 3.35 TB/s ≈ 295 FLOP/byte。向量加法 FP32 强度 1/12 → 极度 memory-bound，评价看带宽利用率；N = 4096 的方阵乘强度 2N/(3s)（FP32 约 683）→ compute-bound。

C21 · 正确测 kernel 时间的五条注意事项？

来源：第 9 章 · 加入 2026-11-14 · 复习记录：

答案
  1. 用 CUDA event（或 CPU 计时器前后都 cudaDeviceSynchronize()）；
  2. 先预热（首次调用有加载 / JIT 开销）；
  3. 重复多次取中位数；
  4. 小输入每次之间清 L2，否则测出比显存还快的"带宽"；
  5. 知道 GPU 会降频，Nsight Compute 默认锁频。

报告有效带宽或 TFLOP/s，并和峰值比。

C22 · Nsight Systems 和 Nsight Compute 各看什么？ncu 报告先看哪几块？

来源：第 9 章 · 加入 2026-11-14 · 复习记录：

答案

nsys：整个程序的时间线，先找最耗时的 kernel 和 GPU 空闲的空隙。ncu：单个 kernel 的深度报告。

ncu 先看：① Speed Of Light（Memory % vs Compute %）；② Roofline；③ Memory Workload（各层流量、sectors / request）；④ Warp State（Long Scoreboard = 等显存，MIO Throttle / Short Scoreboard = shared 压力，Barrier = 等同步）；⑤ Occupancy；⑥ Source 页定位到行。

并行原语

C23 · block 内树形归约怎么写？为什么"前一半加后一半"比"相邻两两"好？

来源：第 10 章 · 加入 2026-11-14 · 复习记录：

答案 
for (d = blockDim.x / 2; d > 0; d /= 2) { __syncthreads(); if (tid < d) s[tid] += s[tid + d]; }

N 个数 log₂N 轮。

前一半加后一半：干活的线程是连续的前 d 个，整个 warp 要么全干要么全歇（只剩不到 32 个时才分岔）；连续线程访问连续地址，无 bank conflict；不用取模。相邻两两（tid % (2s) == 0）每个 warp 都分岔、跨步越来越大造成 bank conflict。

C24 · grid-stride loop 怎么写？有什么好处？

来源：第 10 章 · 加入 2026-11-14 · 复习记录：

答案 
for (i = blockIdx.x * blockDim.x + threadIdx.x; i < n; i += gridDim.x * blockDim.x) acc += a[i];

步长 = 整个 grid 的线程数。好处：block 数与数据量无关（不碰 grid 上限）；每圈整个 grid 合并地读一大段；大部分运算在寄存器里完成，shared 和同步开销被摊薄。

C25 · 四种 warp shuffle 各从哪个 lane 拿值？怎么用 5 步求一个 warp 的和？

来源：第 11 章 · 加入 2026-11-14 · 复习记录：

答案

__shfl_sync（指定 lane，广播）、__shfl_up_sync（lane − d，前缀和）、__shfl_down_sync（lane + d，归约）、__shfl_xor_sync（lane XOR m，蝴蝶归约、全员得结果）。mask 填参与的 lane（通常 0xffffffff）；只能读参与本次 shuffle 的 lane。

for (d = 16; d > 0; d >>= 1) v += __shfl_down_sync(0xffffffff, v, d);   // lane 0 得总和

C26 · 一个高效的归约分哪四层？

来源：第 11 章 · 加入 2026-11-14 · 复习记录：

答案

① 线程内：grid-stride 循环在寄存器里顺序加；② warp 内：5 次 shuffle；③ block 内：每个 warp 的 lane 0 写进 __shared__ ws[32]，同步后第 0 个 warp 再 shuffle；④ 全局：block 的 0 号线程 atomicAdd（或写部分和再起一个 kernel）。Hopper 还可以在 ③④ 之间加一层 cluster（DSMEM）。

C27 · 原子操作解决什么问题？代价是什么？

来源：第 11 章 · 加入 2026-11-14 · 复习记录：

答案

普通 total += x 是读、改、写三步，并发时会丢更新；atomicAdd 等把三步做成不可分的一步，结果一定对。

代价：同一地址的原子操作要排队串行。每个 block 一次没问题；每个线程一次加到同一地址很慢——所以要先在 warp / block 内归约。atomicCAS 能拼出任意原子运算，但用它做锁要小心死锁。

C28 · inclusive 和 exclusive scan 的定义？scan 在并行程序里典型用来干什么？

来源：第 12 章 · 加入 2026-11-14 · 复习记录：

答案

inclusive：v_j = Σ_{i≤j} u_i（含自己）；exclusive：v_j = Σ_{i<j} u_i（不含，v_0 = 0）。[3,1,4,1] → inclusive [3,4,8,9]，exclusive [0,3,4,8]。

典型用途：并行决定每个线程写到哪——每个线程报"我要写几个"，对这些数做 exclusive scan 就是写入起点。过滤、排序、稀疏矩阵、MoE 按专家分组都用它。

C29 · Hillis–Steele 和 Blelloch 两种 scan 的轮数和工作量？

来源：第 12 章 · 加入 2026-11-14 · 复习记录：

答案
轮数 加法次数
Hillis–Steele（每轮加上左边隔 2^k 的数） log₂N ≈ N log₂N（不是 work-efficient）
Blelloch（上扫 + 根清零 + 下扫） 2 log₂N ≈ 2N

N = 8：Hillis–Steele 17 次，Blelloch 14 次。warp 内常用 Hillis–Steele（配 __shfl_up_sync）；跨 block 用三段式或单趟 decoupled look-back（CUB）。

GEMM 与 Tensor Core

C30 · SGEMM 前三步（naive → 合并 → shared 分块）各解决什么问题？A6000 上各到多少？

来源：第 13 章 · 加入 2026-11-14 · 复习记录：

答案
  1. naive：一个线程算一个 C 元素，每次乘加读 8 字节，且 warp 内读 A 不合并 → 309 GFLOP/s（cuBLAS 的 1.3%）；
  2. 合并：让 warp 里连续线程对应 C 同一行的连续列，A 变广播、B 变合并 → 1987（8.5%），只改了映射；
  3. shared 分块：block 合作把 A、B 的 32 × 32 小块搬进 shared，每个显存数被用 32 次 → 2980（12.8%）。

C31 · shared memory 分块的循环骨架？tile 边长 T 时每个显存数被用几次？

来源：第 13 章 · 加入 2026-11-14 · 复习记录：

答案 
for 每一段 K: 搬 As、Bs → __syncthreads() → 用 shared 做 T 次乘加 → __syncthreads()

第一个栅栏保证"搬完再算"，第二个保证"大家算完才覆盖"。每个从显存读进来的数被用 T 次，显存流量降为 naive 的 1/T。

C32 · 寄存器分块为什么让每线程算一个方块，而不是一列？

来源：第 14 章 · 加入 2026-11-14 · 复习记录：

答案

外积写法：每走一步 K，读 A 的一小列 T_M 个、B 的一小行 T_N 个进寄存器，做 T_M × T_N 次乘加。读的是"边"（T_M + T_N），算的是"面积"（T_M T_N）。

每线程 乘加 ÷ 读
1 × 1 0.5
8 × 1 0.89
8 × 8 4

周长相同时正方形面积最大，所以方块最好。代价是寄存器多、occupancy 低，靠 ILP 弥补。

C33 · Boehm SGEMM 从 1.3% 到 93.7% 的完整路线？

来源：第 14 章 · 加入 2026-11-14 · 复习记录：

答案

naive 1.3% → 合并 8.5% → shared 分块 12.8% → 1D 寄存器分块 36.5% → 2D 寄存器分块（外积）68.7% → 向量化（float4、转置 As）78.4% → 自动调参 84.8% → warptiling 93.7%。

C34 · Tensor Core 的 fragment 是什么？m16n8k16 每个线程拿多少个元素？

来源：第 15 章 · 加入 2026-11-14 · 复习记录：

答案

Tensor Core 一条指令让一个 warp 合作算一个小矩阵乘；参与的小矩阵分散存在 32 个线程的寄存器里，每个线程手里那一份叫 fragment。WMMA 不公开布局，mma.sync 的布局写在 PTX 里。

m16n8k16（BF16 进、FP32 累加）：A 16 × 16 每线程 8 个（4 个 32 位寄存器），B 16 × 8 每线程 4 个，D 16 × 8 每线程 4 个 FP32。一条指令 2048 次乘加。

C35 · Ampere 上高性能 GEMM 的内循环是哪三步？swizzle 解决什么？

来源：第 15 章 · 加入 2026-11-14 · 复习记录：

答案

cp.async（显存 → shared，异步）→ ldmatrix（shared → 寄存器，按 mma 需要的布局一次搬好）→ mma.sync（累加器留在寄存器）。

swizzle：写 shared 时把列号和行号做异或，让 ldmatrix 的 32 个行地址不落在同一 bank，消除 bank conflict，又不像 padding 那样破坏对齐。

C36 · wmma / mma.sync / wgmma / tcgen05 四代 MMA 指令的合作单位和同步性？

答案
代 指令 谁发起 同步性 累加器

C37 · cp.async（LDGSTS）和普通的 As[...] = A[...] 有什么区别？

来源：第 16 章 · 加入 2026-11-14 · 复习记录：

答案

普通写法是 LDG（显存 → 寄存器）+ STS（寄存器 → shared），线程会卡住等数据、还占寄存器。cp.async（Ampere 起）一条指令直接显存 → shared、不经寄存器、发出就走；用 commit_group / wait_group（或 barrier / pipeline）等完成。

每个线程默认只等自己发的拷贝，所以等完之后还要 __syncthreads()，别人搬的数据才可见。

C38 · 双缓冲 / S 级流水线怎么排？总时间大约多少？

来源：第 16 章 · 加入 2026-11-14 · 复习记录：

答案

开 S 份 shared buffer，始终有 S − 1 块在路上：发出第 k+1 块的拷贝 → 等第 k 块到齐 → 用第 k 块计算 → 同步后 buffer 才能被覆盖。

n 块、每块搬 t_l、算 t_c：同步写法 n(t_l + t_c)；流水线 ≈ n·max(t_l, t_c) + min(t_l, t_c)。流水线只能把快的那一步藏起来，慢的那一步决定总时间；shared 用量 × S。

C39 · Hopper 的 TMA 是什么？比 cp.async 好在哪？有什么限制？

来源：第 17 章 · 加入 2026-11-14 · 复习记录：

答案

SM 里专门的搬运单元。host 用 cuTensorMapEncodeTiled 建 tensor map（维数、步长、tile 大小、swizzle、越界填充），kernel 里一个线程一条指令搬整块 tile，硬件负责地址计算和越界（自动补 0）；可以 shared → global 写回、写回时归约、multicast 到 cluster 里多个 block。

限制：除最内层外，全局张量每个 stride 必须是 16 字节的倍数。

C40 · mbarrier 怎么判断 TMA 搬的数据到齐了？

来源：第 17 章 · 加入 2026-11-14 · 复习记录：

答案

mbarrier 同时记"还要几次 arrive"和"还要多少字节"。流程：mbarrier.init(mbar, 1) → 线程 0 arrive.expect_tx(mbar, 字节数) → 发 TMA（完成时自动扣字节）→ 所有线程 try_wait.parity(mbar, phase)。两个计数都清零时相位位翻转，等待的线程醒来，数据对它们可见；之后可以下一圈复用。

C41 · thread block cluster 和分布式 shared memory（DSMEM）让 block 之间能做什么？

来源：第 17 章 · 加入 2026-11-14 · 复习记录：

答案

Hopper 起可把相邻几个 block 组成 cluster（__cluster_dims__），保证同时调度到同一个 GPC。cluster 内可以 cluster.sync() 互相等，可以用 cluster.map_shared_rank(ptr, rank) 直接读写对方的 shared memory（DSMEM）。

用途：TMA multicast（一次读、几个 block 同时收到）；跨 block 归约。退出前要再 cluster.sync()，保证没人还在读你的 shared。

C42 · Hopper 的 wgmma 和 Ampere 的 mma.sync 有哪四点不同？

来源：第 18 章 · 加入 2026-11-14 · 复习记录：

答案
  1. 合作单位：warpgroup（4 个连续 warp，128 线程）vs 1 个 warp；
  2. 形状：m64nNk16（N 最大 256）vs m16n8k16；
  3. 操作数：B 必须在 shared、A 在 shared 或寄存器，直接从 shared 读（不用 ldmatrix），shared 布局要符合 swizzle 规定；
  4. 异步：wgmma.fence → mma_async → commit_group → wait_group。

C43 · warp specialization 的结构？full / empty 两组 barrier 各谁 arrive、谁 wait？

来源：第 18 章 · 加入 2026-11-14 · 复习记录：

答案

block 分成生产者 warpgroup（只发 TMA）和消费者 warpgroup（只做 wgmma），中间是 shared memory 环形缓冲区（QSIZE 个 slot）。

  • full[i]：TMA 搬完时 arrive，消费者 wait；
  • empty[i]：消费者算完时 arrive，生产者 wait（初始让生产者以为全空）。

配合 setmaxnreg 寄存器再分配：生产者降到 24 个，消费者升到 240 个。Pranjal 的 H100 GEMM 靠这一结构从 423 涨到 631 TFLOP/s。

C44 · persistent kernel 是什么？它解决哪三个问题？

来源：第 18 章 · 加入 2026-11-14 · 复习记录：

答案

只启动和 SM 数一样多的 block（H100 为 132），每个 block 循环处理多个输出 tile。

① store 结果时生产者已在搬下一个 tile，藏住 store 延迟；② 没有最后一波不满的尾部效应；③ 能自己控制 tile 顺序（分组、Hilbert 曲线）提高 L2 命中率。

C45 · CuTe 的 Layout 是什么？(4,2):(1,4) 把 (3,1) 映射到几？默认步长是什么？

来源：第 19 章 · 加入 2026-11-14 · 复习记录：

答案

Layout = (Shape, Stride)，把坐标映射到一维位置：index = Σ 坐标 × 步长。(4,2):(1,4)：(3,1) → 3·1 + 1·4 = 7（4 × 2 列优先）；(4,2):(2,1) 是行优先。

不写 Stride 时默认 LayoutLeft（广义列优先，和 C 数组习惯相反）。一维坐标按 colexicographical 顺序（最左维变化最快）对应多维坐标。Shape / Stride 可以嵌套。

C46 · CuTe 的 layout 代数有哪几种运算？Atom 的作用？

来源：第 19 章 · 加入 2026-11-14 · 复习记录：

答案

composition（函数复合：重排、reshape、swizzle）、logical_divide（分块：块内坐标 × 第几块）、logical_product（把一个布局复制铺满）、complement。Tensor = 指针 + Layout；local_tile 取 block 的 tile，local_partition 按线程布局切给每个线程。

MMA_Atom / Copy_Atom 把一条硬件指令（mma.sync / wgmma / tcgen05、cp.async / ldmatrix / TMA）需要的线程–值布局包装起来，再用 TiledMMA / TiledCopy 铺满；换架构时主要换 Atom。

C47 · Blackwell 的 tcgen05.mma 和 Hopper 的 wgmma 有哪四点不同？

来源：第 20 章 · 加入 2026-11-14 · 复习记录：

答案
  1. 支持 FP4 / FP6 等更低精度，内建块缩放；
  2. 累加器放 Tensor Memory（TMEM），不占寄存器；
  3. 一个线程发起；
  4. 2-SM MMA：cluster 里相邻两个 CTA 合作，M 最大到 256。

C48 · Tensor Memory 多大、怎么分配、怎么访问？

来源：第 20 章 · 加入 2026-11-14 · 复习记录：

答案

每个 CTA 128 行（lane）× 512 列，每格 32 位 = 256 KB / SM。由一个 warp 用 tcgen05.alloc 按列分配（至少 32 列、2 的幂，一列包含全部 128 行），kernel 结束前必须 tcgen05.dealloc。

只能通过 MMA 写入、tcgen05.ld 读到寄存器、tcgen05.cp / tcgen05.st 写入；每个 warp 只能访问 32 个 lane。

C49 · MXFP8、MXFP4、NVFP4 三种块缩放格式各是多少元素一块、缩放因子是什么类型？

C50 · online softmax 的更新式是什么？两块的 (m, ℓ) 怎么合并？

来源：第 21 章 · 加入 2026-11-14 · 复习记录：

答案

逐个读 x：m′ = max(m, x)，ℓ ← ℓ·e^(m − m′) + e^(x − m′)，m ← m′。旧账按新的最大值打折。

合并：m = max(m₁, m₂)，ℓ = ℓ₁e^(m₁ − m) + ℓ₂e^(m₂ − m)。满足结合律，所以能分块、能并行。softmax 从读三遍变成读两遍。例：[1, 3, 2] 得 ℓ = 1.5032。

C51 · 算子融合省的是什么？AI 里最有价值的几类融合？

来源：第 21 章 · 加入 2026-11-14 · 复习记录：

答案

把相连的运算写进同一个 kernel，中间结果留在寄存器 / shared，不写回显存（再读回来）；memory-bound 时耗时 ∝ 总访存字节，两个合一个约快一倍，还省一次启动。

最有价值：残差加 + RMSNorm / LayerNorm；GEMM + bias + 激活（epilogue）；attention（QKᵀ → softmax → PV）；最后一层 Linear + 交叉熵；量化 + GEMM。

C52 · FlashAttention 的核心做法是什么？为什么结果是精确的？

来源：第 22 章 · 加入 2026-11-14 · 复习记录：

答案

Q 分块，每个 Q 块依次和每个 K、V 块在片上算 S = QKᵀ，用 online softmax 维护 (m, ℓ)，输出 O 每步先乘 e^(m − m′) 打折再累加 P̃V，最后除一次 ℓ。从不把 N × N 的 S、P 写回显存，显存占用 O(N)。

精确：online softmax 的打折修正在数学上等价于整行 softmax。反向不存 P，用 Q、K、V 和保存的 LSE = m + log ℓ 重新算。

C53 · FA2、FA3、FA4 各针对什么瓶颈、用了什么手段？

来源：第 22 章 · 加入 2026-11-14 · 复习记录：

答案
  • FA2（A100）：非矩阵乘 FLOP 贵 16 倍 → 循环里不除 ℓ；SM 吃不满 → 在 Q 维度也并行；按 Q 分 warp 免去 warp 间通信。
  • FA3（H100）：FA2 只有 35% 利用率 → TMA + wgmma + warp specialization、乒乓调度、GEMM 与 softmax 重叠、FP8。FP16 740 TFLOP/s（75%）。
  • FA4（B200）：Tensor Core 翻倍但 exp 单元和 shared 带宽没涨，tile 128 时 exp 与 MMA 都要 1024 周期 → 多项式模拟 exp、条件 rescale、TMEM、2-CTA。最高 1613 TFLOP/s（71%），用 CuTe DSL 写。

C54 · 为什么 LLM decode 是 memory-bound？每个 token 的时间下限怎么估？

来源：第 23 章 · 加入 2026-11-14 · 复习记录：

答案

decode 每步每条序列只处理 1 个 token，矩阵乘退化成矩阵乘向量，算术强度 ≈ batch 大小（BF16 权重时），远低于脊点 295。

每个 token 至少要把全部权重读一遍：下限 = 权重字节 ÷ 显存带宽。Llama-3-8B BF16 约 16 GB ÷ 3.35 TB/s ≈ 4.8 ms，batch 1 上限约 210 token/s。对策：量化权重 / KV、加大 batch、融合。

C55 · paged KV cache 和 split-KV 各解决什么问题？

来源：第 23 章 · 加入 2026-11-14 · 复习记录：

答案

paged KV cache（vLLM）：KV cache 切成固定大小的页，每条序列一张页表记录物理位置，序列变长再分页——解决预留连续空间造成的碎片和浪费；kernel 要先查页表再读。

split-KV：batch 小、序列长时并行度不够，把一条序列的 K、V 切成几段分给几个 SM 各算局部结果和 (m, ℓ)，再用 online softmax 的合并式合起来。

C56 · CUDA 的 Tile 编程模型和 SIMT 有什么不同？

来源：第 24 章 · 加入 2026-11-14 · 复习记录：

答案

SIMT 按单个线程写；Tile 按整个 block 写，描述对 tile（多维数据块）的运算，block 里有几个线程、怎么映射、用不用 shared / 异步 / Tensor Core 都由编译器决定。

C57 · 2026 年写 kernel 的工具从低到高怎么分层？怎么选？

C58 · PTX 和 SASS 有什么区别？cubin 和 PTX 的兼容规则？

来源：第 25 章 · 加入 2026-11-14 · 复习记录：

答案

PTX 是虚拟指令集（compute_XY），SASS 是某一代 GPU 的真实机器码（sm_XY，装在 cubin 里）。fatbin 可同时装多份 cubin 和 PTX，驱动运行时挑最合适的。

C59 · NVRTC 有什么用？Rust 程序调用 C++ kernel 有哪两种方式？

来源：第 25 章 · 加入 2026-11-14 · 复习记录：

C60 · stream 是什么？拷贝和计算重叠需要哪两个前提？默认 stream 有什么坑？

来源：第 26 章 · 加入 2026-11-14 · 复习记录：

答案

stream 是按顺序执行的任务队列；同一 stream 内严格有序，不同 stream 之间可以并发；跨 stream 依赖用 event（cudaEventRecord + cudaStreamWaitEvent）。

C61 · CUDA Graphs 的三步是什么？省掉的是什么？有什么限制？

来源：第 26 章 · 加入 2026-11-14 · 复习记录：

答案

① 捕获（stream capture 或 Graph API 把一串操作录下来）→ ② 实例化（一次）→ ③ 重放（每次一个 cudaGraphLaunch）。省掉的是 CPU 侧每次启动 kernel 的开销，对几百个小 kernel 的 LLM decode 特别有效。

C62 · PDL 怎么用？省掉的是什么？

来源：第 26 章 · 加入 2026-11-14 · 复习记录：

答案

Programmatic Dependent Launch（CC ≥ 9.0）：前一个 kernel 调 cudaTriggerProgrammaticLaunchCompletion()（或所有 block 退出时隐式触发），后一个 kernel 以 PDL 属性启动，提前在空出的 SM 上做准备工作；用前者结果之前必须 cudaGridDependencySynchronize()。

C63 · 优化一个 kernel 的五步流程？怎么证明"对"和"快"？

来源：第 27 章 · 加入 2026-11-14 · 复习记录：

① 先写对（参考实现对拍 + compute-sanitizer）→ ② 判断瓶颈（roofline 三分类）→ ③ 先 nsys 看全局、再 ncu 看单个 → ④ 一次只改一处、记录数字 → ⑤ 和 cuBLAS / FlashAttention / Quack 等基线比、报 SOL 百分比。官方叫 APOD（评估、并行化、优化、部署）循环。

C64 · 三类瓶颈各先试哪些手段？用 AI 写 kernel 要做哪四项检查？

来源：第 27 章 · 加入 2026-11-14 · 复习记录：
